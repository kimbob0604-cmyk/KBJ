- 범위: 코스피200 선물 기준축 + 코스피200 옵션(월물·위클리 월/목) GEX, 주간·야간, 24시간 대시보드, 백테스트, 페이퍼→실전 트레이딩

### 2.2 거래시간·세션·날짜 귀속

| 세션 | 시간 (KST) | 비고 |
|---|---|---|
| 주간 | 08:45 ~ 15:45 | 최종거래일 도래 종목은 15:20 종료 |
| 야간 | 18:00 ~ 익일 06:00 | 주문 접수 17:50~. 선물·미니선물·옵션(위클리 포함). 주간 대비 축소된 가격제한 |

- **야간 거래분은 다음 거래일(T+1)에 귀속**. KRX 데이터도 야간거래 종료일 기준으로 조회
- 모든 레코드에 `session`(day/night)과 `trade_date`(귀속 거래일)를 분리 저장
- 예외 케이스: 금요일 야간(18:00 금 ~ 06:00 토) → 다음 거래일(보통 월요일) 귀속. 월요일 만기 위클리는 이 세션이 만기 직전 세션
- 야간장이 열리는 밤(실측 — `docs/probe_results.md` #19 후속·2026-09-29 분봉): 월~목은 **다음 날이 거래일일 때만**(휴장 전날 밤 없음, 09-23), **금요일은 늘**(월요일 휴장이어도 열림 — 2026-05-22·08-14, 귀속은 다음 거래일). 규칙은 `core.calendar.night_session_opens` 한 곳
- 휴장일: `exchange_calendars`의 XKRX + 수동 오버라이드 파일 `config/holidays_override.yaml` (임시공휴일 대응)
- 시간 저장은 UTC, 표시는 KST. 코드에서 naive datetime 사용 금지

### 2.3 만기 처리

- 위클리 상장 규칙: 월물 최종거래일이 있는 주에는 **월요일 위클리만 상장**, 목요일 위클리 미상장
- 만기 목록과 만기 코드(`fid_mtrt_cnt`)는 **직접 계산하지 말고 KIS 월물리스트 API에서 조회**. 계산 로직은 교차검증용 보조로만 사용
- 만기 시각: 만기일 15:20 KST
- 잔존기간 T: 달력 분 기준 `T = max(분까지남은시간, T_FLOOR) / (365×24×60)`, 기본 `T_FLOOR = 5분`. 0DTE 감마 폭주 방지

### 2.4 GEX 정의·부호·단위

- 가정(naive 딜러 모델): 고객은 콜 매도·풋 매수 → **딜러는 콜 롱, 풋 숏**
- 가격 모델: **Black-76**, 기초자산 = 동일 만기 합성선물 F (ATM 부근 풋-콜 패리티로 추정). 위클리 만기에도 일관 적용 가능, 배당·금리 추정 불필요
- 행사가별:
  - `GEX_call(K) = + Γ_c(K) × OI_c(K) × 250,000 × F² × 0.01`
  - `GEX_put(K)  = − Γ_p(K) × OI_p(K) × 250,000 × F² × 0.01`
- 단위: 원 / 기초자산 1% 변동. 화면 표시는 억원
- 순GEX = 전 행사가·선택 만기 합. 양수 = 롱감마, 음수 = 숏감마
- DEX(딜러 관점): `Σ OI_c·Δ_c·m·F − Σ OI_p·Δ_p·m·F` (풋 델타는 음수이므로 딜러 풋 숏의 델타는 양수)
- Vanna·Charm 익스포저도 동일 부호 규칙 적용
- **부호 규칙은 `tests/test_sign_conventions.py`로 고정.** 변경 시 테스트가 실패해야 함

### 2.5 API 제약

- KIS REST: 초당 호출 한도 준수. 전역 토큰버킷 레이트리미터를 **앱키 단위로 하나만** 운영 (§3 참조)
- KIS 토큰: 유효 24시간, **재발급 1분당 1회**. 토큰 발급은 `auth` 서비스만 수행, 다른 서비스는 Redis 캐시에서 읽기만
- KIS 웹소켓: **앱키당 최대 41건 등록**. 웹소켓 세션 소유는 `ws-gateway` 하나로 한정
- 전광판 콜/풋 API: 콜·풋 각 최대 100건, 권장 호출 1초당 1건 이하
- KRX Open API: 키당 하루 10,000회, 서비스별 이용 신청 필요, 전일 데이터는 다음 영업일 08:00 갱신

### 2.6 이용 조건

- KIS 시세: 계좌 보유 개인의 자기 투자 목적 한정, **제3자 제공 불가** → 대시보드는 비공개(VPN 뒤)
- KRX Open API: 비상업 목적, 가공 표시 시 출처 "한국거래소 통계정보" 표기, 원천 데이터 재배포 금지
- 대시보드·리포트에 두 출처 표기 푸터 고정

### 2.7 코딩 규칙

- Python 3.12, 패키지 관리 `uv`, 린트 `ruff`, 타입 `pyright`(strict: core/, backtest/, exec/)
- 외부 입력은 전부 `pydantic` 모델로 검증 후 내부 사용
- 모든 지표 산출물에 `quality` 필드: `ok | stale | estimated | invalid`
- 예외는 위젯·지표 단위로 격리. 하나의 지표 실패가 수집·다른 지표·대시보드를 멈추면 안 됨
- 로깅: 구조화 JSON, 거래일·세션·서비스명 포함

### 4.3 웹소켓 구독 예산 (41건)

```
주간: 선물 체결 1 + 체결통보 1 + 옵션 체결 38 (ATM±9 행사가 × 콜·풋) + 여유 1
야간: 선물 체결 1 + 체결통보 2 + 옵션 체결 34 (ATM±8 × 콜·풋) + 여유 4
```

- 2026-09-28 정정: 야간 옵션 "36 (ATM±8)"은 계산 오류였다 — ATM±8은 17행사가 × 콜·풋 = 34. 남는 2건은 여유로 돌려 야간 여유 4 (docs/phase1_design.md §4)
- 예산은 `config/ws_budget.yaml`에서 계산식으로 관리. 하드코딩 금지 — 최소 여유(`min_spare`)만 두고 ATM 범위는 식으로 도출(`services/ws_gateway/budget.py`)
- 구독 대상 만기: 최근접 만기(0DTE 또는 차기 위클리)
- ATM 재계산은 1분마다, 기존 구독과 2행사가 이상 차이 날 때만 회전 (잦은 해지·등록 방지)
- 구독 밖 행사가·다른 만기는 REST 전광판 스냅샷 + 단건 현재가 보강(§4.4)으로 채움 (2026-09-28 실측 반영)

### 4.4 수집 주기

| 대상 | 주기 | 호출/주기 |
|---|---|---|
| 전광판 콜/풋: 최근접 만기, 차기 만기, 월물 | 30초 | 3 |
| 선물 전광판·기초자산 | 30초 | 2 |
| 투자자별 매매동향 (F001, OC01, OP01, 위클리 코드) | 60초 | 최대 7 |
| 월물리스트(만기 목록) | 세션 시작 시 + 1시간 | 1~3 |
| 지수선물옵션 마스터(`fo_idx_code_mts`): 만기별 전체 행사가·종목코드. 다섯째 필드는 콜/풋이 아니라 ATM 구분(1 ATM·2 ITM·3 OTM) — 콜/풋은 종목명, 행사가는 여섯째 필드에서 읽는다 (2026-09-28 실측 반영) | `PRE_DAY`·`PRE_NIGHT` 1회 | 파일 1 (REST 한도 밖) |
| 보강 1 — 월물 ATM±20 행사가 × 콜·풋, 옵션 단건 현재가 `FHMIF10000000` (2026-09-28 실측 반영) | 60초 | 82 |

- 전광판 호출 간격은 최소 1초 유지
- 전광판은 콜·풋 각 100행 상한, 행사가 내림차순이라 월물은 ATM 구간이 빠지고 위클리도 먼 행사가가 잘린다(§3 #11). 빠진 행사가는 마스터에서 코드를 얻어 단건 현재가(OI·IV·그릭스 포함, 호가 없음)로 채운다 — 멀티 시세는 옵션 불가, 웹소켓은 예산 부족 (`docs/probe_results.md` #11a, 2026-09-28 실측 반영)
- ATM은 선물가(합성선물 F가 생기면 그것)에 가장 가까운 행사가로 계산한다. 전광판 `atm_cls_name`은 선물가 기준 ATM과 달라 쓰지 않는다 (2026-09-28 실측 반영)
- 전역 레이트리미터(앱키당 1개) 상한은 §3 #10 실측 무오류 단계 5/s 미만. 위 표 합계는 평균 약 2.7건/초(분당 159건: 전광판 6·선물 4·투자자 7·보강 1 82·보강 2 60). `EGW00201` 응답 시 감속(§6.5) (2026-09-28 실측 반영)
- ATM 범위(±20)·보강 2 속도는 초기값. 설정 파일로 관리하고 녹화 데이터로 조정
- 야간 분봉은 시장구분 `CM`으로 조회하고, 봉 시각은 야간 시작일 날짜 + 24~30시 확장 표기라 UTC·`trade_date`로 변환해 저장 (§3 #17, 2026-09-28 실측 반영)
- 야간 전광판 REST가 동작하지 않으면(§3 #19) 야간 체인은 웹소켓 + 직전 주간 스냅샷 OI 기반으로 구성하고 `quality=estimated` 표시

## 5. 지표 명세

각 지표는 `docs/metrics.md`에 아래 형식으로 기록 후 구현: 정의 / 공식 / 입력 / 단위 / 예외 / 품질 판정 / 테스트.

### 5.1 입력 전처리 (모든 지표 공통)

- 옵션 가격: 호가 스프레드 ≤ 3틱이면 mid, 아니면 last. 둘 다 없으면 해당 종목 제외
- 프리미엄 하한: 0.02pt 미만 종목은 IV·그릭스 계산 제외(수치 불안정). 그 OI는 GEX에서 제외하고 `excluded_oi_ratio` 기록. **KIS 그릭스는 어떤 경우에도 쓰지 않는다**(폴백 포함, 2026-09-28 사용자 결정) — GEX는 자체 IV(아래)와 자체 잔존기간 T(§2.3)만 쓰고, KIS 값은 IV 역산 실패 때의 IV 폴백 σ 하나다(자체 T 로 옮긴 값 — 아래 IV, metrics §1.5 T 환산)
- 합성선물 F: ATM±2 행사가의 `C − P + K` 중앙값. 해당 만기가 분기 월물이면 선물가와 비교해 차이가 ±0.5pt 초과 시 `quality=estimated`. 모든 만기의 선물 교차 확인(기준가 = 같은 결제월 선물가, 없으면 근월물 선물가 + 확정 베이시스 — 2pt 초과 `estimated`, 쓸 행사가 2개 미만이면 F = 기준가)은 `docs/metrics.md` §1.3 (2026-09-28 사용자 결정)
- IV: Black-76 역산, `py_vollib`(Let's Be Rational) 사용. 실패 시 KIS `hts_ints_vltl` 폴백 + `estimated` — 폴백 σ 는 σ_KIS·√(T_KIS/T)(T_KIS = metrics §1.7 KIS 관례, T = §2.3 자체 T)로 자체 T 에 옮긴 뒤 §6.1 이상치 판정. 옮긴 탓에 이상치가 된 행은 `invalid`(사유 `kis_out_of_range_rescaled`)로 빠지고 옮긴 기록은 남는다 (2026-09-28 사용자 결정, metrics §1.5)

| 딜러 가정 점검 | 증권 계정의 콜·풋 누적 순매수 방향이 naive 가정(딜러 콜 롱·풋 숏)과 일치하는지 일별 기록 | 플로우(거래)이지 포지션(OI) 아님을 명시. 불일치 지속 시 대시보드 경고 배지 |
| 대량 체결 | 1틱 체결량 ≥ 최근 20거래일 동일 머니니스 구간 p99 | 초기 20일은 비활성 |
| PCR | OI 기준, 거래량 기준 | — |
| 맥스페인 | 옵션 매수자 총 내재가치 합이 최소가 되는 행사가 | 만기별 |
| OI 증감 히트맵 | 행사가 × 시간 OI 변화 | 스냅샷 간 OI 역행(감소 후 즉시 복구) 등 이상치 격리 |

### 5.6 선물

- 시장 베이시스, 이론 베이시스, 괴리율, 선물 OI 증감, 체결강도: KIS 선물 체결 필드 그대로 사용 + 자체 계산값 교차검증

### 5.7 레벨 준수 통계 (백테스트 산출물을 대시보드에 표시)

- 예: "롱감마 레짐에서 콜월이 해당 세션 고가 위 0.3% 이내에서 막힌 비율", "전환점 하향 이탈 후 다음 세션 변동폭 중앙값"
- 표본 기간과 표본 수를 항상 같이 표시. 위클리 시대 구분(§9.6)별로 분리

## 6. 오류 방지 설계

### 6.1 데이터 품질 게이트

- 수집 즉시 pydantic 검증. 실패 레코드는 `quarantine` 테이블로 격리
- 이상치 규칙(초기값, 운영하며 조정):
  - OI 음수, IV ≤ 0 또는 > 300%, 가격 < 0
  - 타임스탬프 역전, 미래 시각
  - 스냅샷 간 행사가 개수 급감(> 20%)
  - 선물가와 합성선물 차이 > 2pt
- `stale` 기준: 웹소켓 10초, REST 스냅샷 90초 미갱신

### 6.2 교차검증 (자동 테스트 + 운영 모니터)

| 비교 | 초기 허용오차 | 조치 |
|---|---|---|
| KIS 관례 재현 — 델타: 자체 `core.greeks`(Black-76)에 KIS 가 쓰는 입력(σ·S·T, `docs/metrics.md` §1.7)을 넣어 KIS `delta_val` 을 다시 낸다 (ATM±5) — 2026-09-28 사용자 결정 | 평이 상대오차(`자체/KIS − 1`) 1% [확인 필요]. KIS 4자리 반올림 구간 밖 상대오차(반올림 보정)도 나란히 기록 — 제안 [확인 필요] | 초과 시 경고 + 원인(반올림·S·σ√T) 기록. 자체 공식 구현 검증용 |
| KIS 관례 재현 — 감마: 같은 입력으로 KIS `gama` 를 다시 낸다 (ATM±5) — 2026-09-28 사용자 결정 | 동일 | 동일 |
| 장 마감 자체 IV vs KRX IMP_VOLT (다음날 08:00) | 차이 분포를 30일 수집 후 p95로 허용오차 확정 | 차이 급변 시 경고 |
| KIS 마지막 스냅샷 OI vs KRX ACC_OPNINT_QTY | 완전 일치(0) 기대 | 불일치 시 해당일 백테스트 데이터 플래그 |
| 자체 만기 계산 vs KIS 월물리스트 | 완전 일치 | 불일치 시 KIS 값 사용 + 경고 |

- 2026-09-28 사용자 결정: 1·2줄은 자체 값과 KIS 값을 직접 비교하던 것(자체 감마 vs KIS 감마 상대오차 5%, 자체 IV vs KIS IV 1.0%p)을 **KIS 관례 재현 검사**로 바꿨다. KIS 그릭스·IV 는 자체와 다른 관례(월물 σ = 역사적 변동성, 만기일 T = 0.5일 등 — metrics §1.7)로 매겨져 자체 값의 정답이 아니다. 재현 검사는 같은 입력이면 자체 Black-76 이 KIS 값을 내는지 — 공식 구현 — 를 본다. 자체 IV·감마와 KIS 값의 차는 판정하지 않고 기록만 한다(`docs/validation_greeks.md`)
- 판정 오차는 결정대로 평이 상대오차다. 2026-09-28 실측: 월물 ATM±5 는 평이·반올림 보정 두 기준 모두 전 행 재현. 전체 행은 반올림 보정 기준에서만 전 행이다 — ATM±5 밖의 작은 KIS 값(감마 0.0001~0.0029, 델타 0.0016~0.0047)은 4자리 반올림 폭만으로 1% 를 넘는다(원인 `반올림`, metrics §1.7)
- **KIS 그릭스는 어떤 경우에도 폴백으로 쓰지 않는다.** GEX 는 자체 IV(§5.1)와 자체 잔존기간 T(§2.3)만 쓴다 — KIS 값이 들어가는 곳은 §5.1 IV 역산 실패 때의 IV 폴백 σ 하나다(자체 T 로 옮긴 값 — §5.1)

### 6.3 테스트 체계

- 단위: Black-76 가격·그릭스(문헌·`py_vollib` 기준값), IV 역산 왕복, 틱 반올림, 세션 귀속
- 속성 기반(`hypothesis`): 감마 ≥ 0, 콜·풋 감마 동일(같은 K·T·σ), 풋-콜 패리티, 순GEX의 콜/풋 대칭성, Flip이 격자 범위 안
- 캘린더 케이스 고정 테스트:
  - 월물 만기주(월요일 위클리만 존재)
  - 금요일 야간 → 월요일 귀속
  - 월요일 휴장 시 월요일 위클리 만기 순연
  - 목요일 휴장 시 월물 만기 앞당김
- 골든(리플레이): 주간·야간 각 1일 이상 녹화 fixture → 전체 파이프라인 출력 스냅샷 비교
- 통합: Docker Compose 테스트 스택에서 리플레이로 전 서비스 기동, 대시보드 API 응답 검증

### 6.4 기능 플래그와 섀도 모드

- `config/features.yaml`: 지표·위젯·알림·전략 단위 on/off
- 신규 지표는 `shadow` 상태로 계산·저장만 → 교차검증·육안 검토 통과 후 `visible`
- 감마랩 7일 무료체험 기간에 같은 시각의 콜월·풋월·전환점 대조 기록 (`docs/validation_gammalab.md`). 차이는 오류가 아니라 모델 차이일 수 있으므로 원인 분류

### 6.5 장애 격리

- 서비스별 컨테이너 분리, `restart: always` + healthcheck
- 엔진은 지표별 try/except로 격리, 실패 지표는 `invalid` 발행 후 계속 진행
- 웹소켓 재연결: 지수 백오프(1s→60s), 재연결 후 REST 스냅샷으로 상태 복구, HIRO-lite 리셋
- REST `초당 거래건수 초과` 응답 시 레이트리미터 자동 감속

### 6.6 개발 파이프라인

- pre-commit: ruff, ruff-format, pyright, pytest(unit+property, 빠른 셋)
- Claude Code 훅(PostToolUse, Edit/Write 대상): ruff + 변경 모듈 관련 pytest 실행, 실패 시 즉시 수정

## 9. 백테스트

### 9.1 데이터 계층

| 계층 | 기간 | 소스 | 용도 |
|---|---|---|---|
| 일봉 GEX | 2010-01-04 ~ | KRX Open API 옵션·선물 일별 | 신호 유효성 검증, 일봉 전략 |
| 선물 분봉 | 실측 범위(§3 #17) | KIS 분봉 조회 | 일봉 신호 + 장중 진입·청산 시뮬레이션 |
| 장중 GEX | 녹화 시작일 ~ | 자체 recorder | 장중 전략, 만기 핀 전략 |

- KRX 백필: 날짜당 옵션·선물 각 1회 호출, 10,000회/일 한도 내 1~2일에 완료. 응답 원본을 Parquet로 보관
- KRX 일별 IV는 IMP_VOLT 사용 + 종가로 자체 IV 재계산 병행 저장

### 9.2 시점 정합성 (룩어헤드 방지)

- 일봉: T일 KRX 데이터(T+1 08:00 공개)로 만든 신호는 **T+1 주간 세션부터** 사용
- 라이브에서는 T일 장 마감 KIS 스냅샷으로 먼저 계산하되, 백테스트와 동일 입력이 되도록 "마감 스냅샷 = KRX 값" 일치 여부를 §6.2로 검증
- 장중: 스냅샷 수신 시각 이후 다음 바에서만 체결
- 야간 세션 데이터는 T+1 귀속 규칙을 그대로 적용

### 9.3 연결선물

- 롤 규칙(기본): 최종거래일 직전 거래일 장 마감에 차월물로 롤. 대안 규칙(미결제약정 역전일)도 파라미터로 제공
- 가격 조정 연결선물(수익률 계산용)과 원가격(레벨 비교용) 두 계열 모두 생성
- 레벨(콜월 등)은 지수·옵션 기준 → 선물 비교 시 베이시스 보정 규칙 명시

### 9.4 비용·체결 모델

- 수수료: `config`의 계약당 금액(사용자 계좌 요율 입력)
- 슬리피지: 기본 주간 1틱, 야간 2틱. 0·1·2·3틱 민감도 리포트 필수
- 체결: 다음 바 시가 또는 지정가 도달 시. 가격제한(야간 축소 제한 포함) 도달 시 미체결 처리
- 만기일·서킷브레이커·사이드카 발동일 플래그

### 9.5 엔진

- 이벤트 기반, 바 단위(일봉·분봉) 공통 인터페이스
- 전략 인터페이스(`strategy/base.py`): `on_bar(state) -> list[Order]`, 입력 `state`는 가격·레벨·지표·품질 포함. **라이브 `trader`와 동일 클래스 사용**
- 포지션 사이징: 고정 계약 수 / 변동성 역가중 두 모드
- 산출: 수익곡선, CAGR, MDD, 샤프, 소르티노, 프로핏팩터, 승률, 평균손익비, 거래 수, 보유시간, 레짐별·세션별·요일별·만기주 여부별 분해

### 9.6 검증 절차

1. **신호 유효성 검증(전략보다 먼저)**
   - 순GEX 부호별 다음 세션 실현변동폭(고저폭, 절대수익률) 분포 비교 — 숏감마일 때 유의하게 큰지
   - Flip 하향 이탈 후 수익률 자기상관(추세 지속 여부)
   - 롱감마 레짐에서 콜월·풋월의 고가·저가 제한 빈도 vs 무작위 레벨 대조군
   - 딜러 가정 점검 결과(§5.5)와 신호 성과의 관계
2. **시대 구분**: 월물만(2010~목요일 위클리 등장 전), 목요일 위클리 시대, 월·목 위클리 시대(2023.7.31~). 경계일은 KRX 데이터에서 위클리 종목 최초 등장일로 자동 판정
3. **과최적화 통제**: 전략당 튜닝 파라미터 ≤ 3개, 사전 등록한 파라미터 격자만 탐색, 워크포워드(학습 3년 / 검증 1년 롤링), 최종 1년은 홀드아웃으로 봉인
4. 페이퍼 결과와 백테스트 괴리 분석을 실전 전 필수 단계로 둠

### 9.7 전략 가설 (모두 검증 전)

| ID | 이름 | 규칙 개요 | 필요 데이터 |
|---|---|---|---|
| S1 | 레짐 스위칭 | 순GEX > 0이면 기대범위 경계 역추세, 순GEX < 0이고 F < Flip이면 돌파 추세추종 | 일봉 + 선물 분봉 |
| S2 | 벽 반전 | 롱감마 레짐에서 콜월 근처(±0.2%) 매도, 풋월 근처 매수. 손절 = 벽 돌파 + α, 목표 = 절대감마 행사가 | 선물 분봉 |
| S3 | 전환점 이탈 | F가 Flip 하향 이탈(히스테리시스 포함) 시 매도, 재회복 시 청산 | 장중 GEX(녹화) 또는 일봉 근사 |
| S4 | 만기 핀 | 만기일 13:00 이후 최대 GEX 행사가로 수렴 가정, 이탈 폭 역방향 진입 | 장중 GEX(녹화) |
| S5 | 필터 오버레이 | 기본 추세/돌파 신호에 GEX 조건(레짐·거리)을 걸어 거래 수 감소 대비 성과 개선 측정 | 일봉 + 선물 분봉 |

## 10. 실행과 리스크 관리

### 10.1 단계

1. 자체 페이퍼 브로커(주간·야간): 라이브 호가 기반 가상 체결, §9.4 체결 모델과 동일 규칙
2. KIS 모의 주문(주간만): 주문·정정·취소·체결통보 흐름 검증용
3. 실전 소액(Phase 9): 미니선물 1계약 수준부터

### 10.2 리스크 한도 (`exec/risk.py`, 주문 전 필수 통과)

- 최대 포지션 계약 수, 세션당 최대 신규 주문 수
- 일 손실 한도, 연속 손실 N회 시 당일 정지
- 데이터 품질 게이트: 선물 피드 `stale` 또는 레벨 `invalid`면 신규 진입 금지
- 개장 직후 N분·만기일 마감 전 N분 신규 진입 금지(설정값)
- 가격제한폭 근접 시 신규 진입 금지(야간 축소 제한 반영)
- 킬스위치: 텔레그램 `/kill`, 파일 플래그, 대시보드 버튼 → 신규 주문 즉시 차단

### 10.3 주문 무결성

- 주문마다 멱등 키 부여, 재시도 시 중복 주문 방지
- 가격은 `Decimal` + 틱 반올림, 전송 전 스키마 검증
- 기본 주문 유형: 지정가 IOC. 시장가는 청산·킬스위치에만 허용
- 60초마다 잔고 대사(KIS 잔고 vs 내부 포지션). 불일치 시 신규 주문 차단 + 알림
- `LIVE_TRADING=true` + 대시보드 수동 확인 둘 다 있어야 실전 브로커 활성

### 10.4 사용자 사전 준비 (코드 범위 밖)

- 파생상품 계좌 개설 요건(사전교육·모의거래·기본예탁금) 충족 여부 확인
- 선물옵션 계좌 Open API 신청, 실전·모의 앱키 발급

## 11. 24시간 인프라

### 11.1 호스팅

- 운영: 서울 리전 클라우드 VM, Ubuntu LTS. 권장 사양(추정): 2 vCPU / 8GB RAM / SSD 100GB 이상. 녹화량 실측 후 조정
- 개발·장애 대비: 맥북에서 동일 `docker compose` 기동 가능하게 유지
- 시간: VM TZ는 UTC 유지, chrony로 NTP 동기화, 앱에서 KST 변환

### 11.2 접근 보안

- 공개 포트 없음. Tailscale로 맥·휴대폰만 접속 (대안: Cloudflare Tunnel + Access 이메일 인증)
- SSH는 Tailscale 경유만 허용, 비밀번호 로그인 금지
- `.env`는 VM에 수동 배치, 권한 600

### 11.3 가용성·감시

- 컨테이너 `restart: always` + healthcheck, 호스트 재부팅 시 자동 기동(systemd로 compose 관리)
- 외부 하트비트: Healthchecks.io(또는 Uptime Kuma) — `engine`·`ws-gateway`가 1분마다 핑, 끊기면 텔레그램 알림
- 디스크 사용률·DB 크기 모니터, 80% 경고
- 로그 로테이션(Docker json-file max-size), 30일 보관

### 11.4 백업·복구

- 매일 `POST_DAY`에 Parquet 내보내기 → 외부 저장소(오브젝트 스토리지 또는 Google Drive) 업로드
- DB 덤프 주 1회, 복구 절차를 `docs/runbook.md`에 기록하고 분기 1회 복구 리허설

### 11.5 배포

- 맥에서 Claude Code 개발 → private GitHub push → Actions 통과 → `scripts/deploy.sh`(VM에서 `git pull && docker compose pull && docker compose up -d`)
- 배포는 `IDLE` 또는 `POST_DAY` 상태에서만 허용(스크립트가 세션 상태 확인)
- 롤백: 직전 이미지 태그로 재기동

## 13. 알려진 한계

- naive 딜러 가정의 오류 가능성: 국장은 개인·외국인 방향성 옵션 매수 비중이 커서 GEX 부호 자체가 틀릴 수 있음. 투자자별 합계(증권 계정)로 점검은 가능하나 행사가별 보정은 불가
- KIS 그릭스와 자체 모델 간 차이는 모델 가정 차이일 수 있음 — 허용오차는 실측 기반으로 확정
- 일봉 백테스트는 장중 레벨 변화를 반영하지 못함. 장중 전략의 통계적 신뢰도는 녹화 기간이 길어져야 확보
- 과거 성과는 미래 성과를 보장하지 않음. 모든 전략은 검증 전 가설
