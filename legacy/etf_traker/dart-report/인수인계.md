## 2. CLAUDE.md

이미 폴더에 있습니다. Claude Code가 매 세션 자동으로 읽으므로 프롬프트에 다시 붙일 필요 없습니다.

내용 요약 — 왜 필요한지:

- **데이터 신뢰도 3단계**: 정형 API(높음) / 주석 파싱(중간) / 사용자 가정(변동비·고정비 구분). 섞어 쓰면 틀린 리포트가 나옵니다.
- **깨뜨리면 안 되는 것 4가지**: 합계는 엑셀 수식으로, 파란글씨=원천값 검은글씨=수식, 브릿지 잔차 플러그 삭제 금지, 수식 수정 후 재계산 검증 필수.
- **이미 밟은 지뢰**: 누적→분기 차분, 행 인덱스 off-by-one(OPM 선이 영업이익을 그리던 버그), 이중축 `crosses="max"`, 데이터 레이블 플래그, LibreOffice 락 파일, 정정공시 중복.

특히 **브릿지 잔차 플러그**는 코드만 보면 쓸데없어 보여서 지우기 쉽습니다. 지우면 주석 파싱이 실패했을 때 조용히 틀린 워터폴이 나갑니다.

## 3. 프롬프트

### 첫 작업 — 매핑 튜닝 (이게 먼저입니다)

실데이터로 한 번도 안 돌려봤습니다. 회사마다 주석 계정명이 달라서 첫 실행에는 미매핑이 대량으로 나옵니다.

```
DART_API_KEY는 환경변수에 있어.

006110으로 --diagnose-costs를 돌려서 미매핑 계정 목록을 뽑고,
config/mapping.yaml의 buckets에 채워 넣어줘.
매핑은 부분문자열 선착순 매칭이니 구체적인 항목을 일반 항목보다 앞에 둬야 해.

채운 뒤 다시 돌려서 세 가지를 알려줘:
1. 미매핑 계정이 몇 개에서 몇 개로 줄었는지
2. 브릿지 잔차가 얼마나 작아졌는지
3. 비용합계로 역산한 영업이익과 손익계산서 공시 영업이익의 차이
```

### 종목 확대

```
005930으로도 돌려봐. 주석 구조가 달라서 파싱이 깨지면
costs.py를 고치기 전에 mapping.yaml로 해결되는지 먼저 확인해줘.
```

### 양식 수정

```
분기실적 시트에 QoQ·YoY 증감률 행을 추가해줘.
값이 아니라 수식으로 넣고, 넣은 뒤 재계산 검증해서 오류 0인지 확인해줘.
```

### 넣지 말아야 할 요청

- "비용 분해를 API에서 바로 가져와줘" — 정형 API에 그 데이터가 없습니다. 주석 파싱 말고 방법이 없습니다.
- **API 키를 프롬프트 본문에 붙여넣지 마세요.** 대화 기록에 남습니다. `export DART_API_KEY=...`로만 넘기세요.
