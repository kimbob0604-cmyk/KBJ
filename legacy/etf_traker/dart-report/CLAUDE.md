# CLAUDE.md

DART OpenAPI 로 국내 상장사 재무 데이터를 받아 정해진 양식의 엑셀 리포트를 만드는 도구.
종목코드만 바꾸면 어느 종목이든 돌아가야 한다.

## 실행

```bash
export DART_API_KEY=...            # 절대 코드에 하드코딩하지 말 것
pip install -r requirements.txt

python run.py --stock 006110 --years 2023 2026   # CLI
python run.py --stock 006110 --diagnose-costs    # 매핑 튜닝용 진단
streamlit run app.py                             # 웹 UI
python tests_smoke.py                            # API 키 없이 합성 데이터로 빌더 검증
```

## 구조

| 파일 | 역할 |
|---|---|
| `dartreport/client.py` | DART API 래퍼. 디스크 캐시, 스로틀, status 013(데이터없음)을 에러가 아닌 빈값으로 처리 |
| `dartreport/statements.py` | 재무제표 수집 + **누적→분기 차분** |
| `dartreport/costs.py` | 정기보고서 주석 '비용의 성격별 분류' 파싱 |
| `dartreport/orders.py` | 단일판매·공급계약 공시 파싱 |
| `dartreport/bridge.py` | 영업이익→당기순이익 워터폴 |
| `dartreport/excel.py` | 워크북 빌더 (8시트 + 차트 4개) |
| `config/mapping.yaml` | 계정명 동의어 사전. **코드 수정 대신 여기를 먼저 고칠 것** |

## 데이터 신뢰도 — 이걸 모르면 틀린 리포트를 만든다

블록마다 출처가 다르고 신뢰도가 다르다. 섞어서 취급하지 말 것.

- **높음 (정형 API)**: 분기 실적, 브릿지의 영업이익·세전이익·법인세·순이익. `fnlttSinglAcntAll` 공시값 그대로.
- **중간 (주석 파싱)**: 비용 7항목 분해, 브릿지 세부(FVPL·순이자·순외환), 수주 내역. 회사마다 계정명이 달라서 **첫 실행 시 거의 항상 매핑 보강이 필요하다.**
- **가정 (사용자 설정)**: `cost_behavior` 의 변동비/고정비 구분. 회계 기준이 아니라 분석 가정이다.

정형 API 에는 비용 성격별 분해가 없다. 주석 파싱 말고 다른 방법은 없으니 "API 에서 가져오면 되지 않나"로 되돌아가지 말 것.

## 깨뜨리면 안 되는 것

1. **합계·비율은 반드시 엑셀 수식.** 파이썬에서 계산한 결과를 값으로 박지 말 것. 사용자가 셀을 고치면 다시 계산돼야 한다.
2. **색 규칙**: 파란 글씨 = DART 원천값, 검은 글씨 = 수식. 섞지 말 것.
3. **브릿지의 잔차 플러그(`기타 영업외손익`)를 제거하지 말 것.** 주석 분해가 실패해도 브릿지가 공시 세전이익에 강제로 맞도록 하는 장치다. 잔차가 크다는 건 "숫자가 틀렸다"가 아니라 "매핑을 더 해야 한다"는 신호다. 이걸 빼면 조용히 틀린 워터폴이 나간다.
4. **수식을 건드렸으면 반드시 재계산 검증**을 돌리고 오류 0 을 확인한 뒤에 넘길 것. 현재 기준 수식 197개.

## 이미 밟은 지뢰 (다시 밟지 말 것)

- **누적 차분**: DART 손익계산서는 누적이다. Q2 = 반기 − 1Q, Q4 = 연간 − 3Q누적. 손익 항목은 `thstrm_add_amount`(누적)를 우선하고, 재무상태표 항목은 시점값이라 차분하면 안 된다.
- **행 인덱스 off-by-one**: `excel.py` 는 `rr` 커서를 증가시키며 행을 쌓는데, 블록마다 마지막에 `rr += 1` 을 하는 곳과 안 하는 곳이 섞여 있다. 차트가 참조할 행 번호를 잡을 때 **반드시 생성된 xlsx 의 차트 XML 에서 실제 참조 범위를 확인할 것.** 실제로 OPM 선이 영업이익 행을 그리는 버그가 있었다.
- **이중축**: 보조축에 `y_axis.crosses = "max"` 를 주지 않으면 두 축이 모두 왼쪽에 겹쳐 그려진다. `axId` 도 차트마다 다른 값이어야 한다.
- **데이터 레이블**: `DataLabelList()` 에서 지정하지 않은 플래그를 일부 뷰어가 '켜짐'으로 해석해 계열명이 겹쳐 찍힌다. `_labels()` 헬퍼가 모든 플래그를 명시적으로 끄니 이걸 쓸 것. 계열×범주가 20개를 넘으면 레이블은 끄는 게 맞다.
- **LibreOffice**: 변환이 실패한 뒤 `.~lock.*#` 파일이 남으면 이후 모든 재계산이 타임아웃한다. 프로필(`~/.config/libreoffice`)을 지우지 말고 **락 파일부터 지울 것.**
- **정정공시**: 같은 계약이 원본과 정정으로 두 번 잡힌다. `rcept_no` 가 큰 쪽만 남긴다.

## 실데이터 검증 상태 (2026-09-01, 006110·005930)

비용 파싱은 실데이터로 검증됐다. 역산 영업이익(매출−비용합계) vs 공시 영업이익:
- 006110 삼아알미늄: 2023~1H26 전부 차이 0.0억, 미매핑 0
- 005930 삼성전자: 연간(2023·2024·2025) 전부 차이 0.0억, 미매핑 1종
  (rowspan 이 라벨을 삼킨 재고변동 행 — 합계는 정확, 원가/기타 구분만 흐림)

이 과정에서 파서에 들어간 것: 단위 배율(표 안팎의 '단위: 천원' 류), 누적 열
선택(반기·분기 표의 첫 숫자열은 3개월), 정형 API 기대 총비용(매출−영업이익)
±5% 대조로 연결/별도 표 구분, 라벨 없는 합계행 탐지(값 ≈ 나머지 합).
진단은 `--diagnose-costs` 가 원시 행·배율·합계까지 찍는다. 실행은 GitHub
Actions 러너에서만 가능하다(개발 샌드박스는 DART 접속 불가) — 로그가 눈이다.

## 아직 안 된 것

- **브릿지 주석 매핑.** 잔차 플러그가 흡수 중: 006110 37.6억, 005930 -10.2조.
  브릿지는 여러 표를 merge 해 연결·별도가 이중합산될 수 있다 — 비용 파싱에
  넣은 기대값 대조를 브릿지에도 적용하는 게 다음 작업.
- **005930 분기 누적 일부 괴리.** 연간은 정확하지만 2Q25(-2.6%)·3Q25(-31%)·
  2Q26(+1.7%)의 분기보고서에서 기대 총비용과 맞는 표를 못 찾았다(로그에
  '합 vs 기대'로 표시됨). 해당 분기의 분기 비용구조 차분이 흐려진다.
- 매핑은 부분문자열 선착순 매칭이라 **구체적인 항목을 일반적인 항목보다 앞에 둬야 한다.**
