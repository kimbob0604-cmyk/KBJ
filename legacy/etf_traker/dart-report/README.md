# DART 재무 리포트 생성기

종목코드 하나를 넣으면 DART OpenAPI에서 데이터를 받아, 정해진 6블록 양식의 엑셀 리포트를 만듭니다.

## 무엇이 어디서 오는가

이게 이 도구에서 가장 중요한 부분입니다. **여섯 블록이 전부 같은 신뢰도로 나오지 않습니다.**

| 블록 | 출처 | 신뢰도 |
|---|---|---|
| 분기 실적 (매출·영업이익·순이익·OPM) | `fnlttSinglAcntAll` 정형 API | 높음 — 공시 숫자 그대로 |
| 이익 브릿지 골격 (영업이익·세전이익·법인세·순이익) | 같은 정형 API | 높음 |
| 이익 브릿지 분해 (FVPL·이자·외환·배당) | 정기보고서 **주석 파싱** | 중간 — 잔차로 검증 |
| 연간/분기 비용 성격별 분해 | 정기보고서 **주석 파싱** | 중간 — 계정명 매핑 필요 |
| 수주 현황 | 거래소공시 **원문 파싱** | 중간 — 서식 편차 있음 |
| 변동비/고정비 구분 | `config/mapping.yaml` 분석 가정 | 사용자 설정 (회계 기준 아님) |

정형 API에는 비용 성격별 분해가 **없습니다.** 그래서 주석 표를 직접 읽는데, 계정명이 회사마다 달라 첫 실행 후 매핑을 한 번 손보는 것이 정상 워크플로입니다. 아래 "매핑 튜닝" 참고.

## 설치

```bash
pip install -r requirements.txt
export DART_API_KEY='발급받은40자리키'      # https://opendart.fss.or.kr 무료, 하루 20,000건
```

인증키는 코드에 절대 넣지 마세요. 환경변수나 GitHub Secret으로만 다룹니다.

## 사용법

### 1. 명령줄

```bash
python run.py --stock 006110
python run.py --stock 006110 --years 2023 2026 --fs-div CFS
python run.py --stock 006110 --no-orders          # 수주 수집 생략 (빠름)
```

결과: `out/{회사명}_{종목코드}_재무리포트.xlsx`

### 2. 웹 앱

```bash
streamlit run app.py        # http://localhost:8501
```

사이드바에 종목코드를 넣고 버튼을 누르면 화면에서 차트를 보고 엑셀로 내려받습니다.

### 3. GitHub Actions

1. 이 폴더를 레포에 올립니다.
2. `Settings → Secrets and variables → Actions → New repository secret`
   - Name: `DART_API_KEY`, Value: 발급받은 키
3. (선택) 같은 화면 `Variables` 탭에 `STOCKS` = `006110,005930` 처럼 종목 목록 등록
4. `Actions → DART 재무 리포트 → Run workflow` 로 수동 실행하거나, 분기보고서 마감 직후(2/5/8/11월 16일)에 자동 실행됩니다.

결과 xlsx는 워크플로 실행의 Artifacts에 붙습니다.

## 엑셀 시트 구성

| 시트 | 대응 | 내용 |
|---|---|---|
| `요약` | — | 회사 정보 · 출처 · 경고 |
| `연간비용구조` | 이미지 1 | 연도별 매출/비용 7항목/영업이익 + 비용누적 막대 & OPM 보조축 |
| `분기실적` | 이미지 2 | 분기 막대 + OPM 보조축 선 차트 |
| `이익브릿지` | 이미지 3 | 영업이익 → 순이익 워터폴 |
| `수주현황` | 이미지 4 | 계약별 표 + NIPA 비중 |
| `분기비용구조` | 이미지 5·6 | 분기 비용표(변동비/고정비, 공헌이익률) + 100% 누적 차트 |
| `RAW_분기재무` | — | 원천 계정값 |
| `RAW_미매핑계정` | — | 매핑 튜닝용 진단 |

파란 글씨 = DART 원천값, 검은 글씨 = 수식. 합계·이익률은 전부 수식이라 값을 고치면 다시 계산됩니다.

### 차트

차트 4개가 자동 생성되며, 전부 시트의 셀 범위를 참조합니다 — 값을 고치면 차트도 따라 움직입니다
(이미지로 붙여넣은 게 아닙니다).

| 차트 | 위치 | 형태 |
|---|---|---|
| 연도별 비용 구조와 마진 | `연간비용구조` | 비용 7항목 누적 막대 + OPM 선(보조축) |
| 분기 실적 추이 | `분기실적` | 매출·영업이익·순이익 묶은 막대 + OPM 선(보조축) |
| 이익의 질 | `이익브릿지` | 워터폴 (투명 '받침' 계열로 계단 구현) |
| 분기별 비용 구성 | `분기비용구조` | 100% 누적 막대 |

데이터 레이블은 밀도가 낮은 워터폴에만 켜져 있습니다. 분기 차트는 14분기 × 3계열 = 42개,
비용 구성은 7계열 × 14분기 = 98개라 레이블을 켜면 서로 겹쳐 읽을 수 없어서, 숫자는 바로 위 표에서
읽도록 했습니다. 켜고 싶으면 `dartreport/excel.py` 의 `_labels(show=False)` 를 `show=True` 로 바꾸세요.

## 매핑 튜닝 (첫 실행 후 한 번)

주석 계정명은 회사마다 다릅니다. 실제로 뭐가 나오는지 먼저 보세요.

```bash
python run.py --stock 006110 --diagnose-costs
```

미매핑 계정이 출력되면 `config/mapping.yaml` 의 `buckets` 에 추가합니다.

```yaml
buckets:
  외주용역비:
    - 외주용역비
    - 지급용역비      # ← 이 회사가 쓰는 표현을 추가
```

매칭은 **공백 제거 후 부분문자열 포함**이고, 위에서부터 먼저 맞는 버킷이 이깁니다. 그래서 구체적인 항목(`무형자산상각비`)을 포괄적인 항목(`상각비`)보다 위에 둬야 합니다.

주석 표 자체를 못 찾으면 `note_titles` 를 넓히세요. 보고서마다 "비용의 성격별 분류" / "영업비용" 등 표제가 다릅니다.

## 검증 포인트

리포트를 믿기 전에 세 가지를 확인하세요.

**첫째, 이익브릿지의 잔차.** `기타 영업외손익` 행이 크면 주석 분해가 안 된 것입니다. 브릿지는 항상 세전이익에 맞도록 잔차를 플러그로 넣기 때문에, 숫자가 틀리는 대신 잔차가 커집니다.

**둘째, 비용합계와 공시 영업이익의 차이.** `연간비용구조` 의 영업이익은 매출액−비용합계로 역산한 값입니다. `분기실적` 시트의 공시 영업이익과 크게 다르면 주석 표를 잘못 잡은 것입니다.

**셋째, 수주 표의 정정공시.** 정정 건은 별도 행으로 남습니다. 원계약과 중복 집계되지 않았는지 `정정` 열을 보고 확인하세요.

## 알려진 한계

- 분기 값은 누적 차분이라 **직전 분기 보고서가 없으면 산출 불가**입니다 (해당 분기는 빈칸 + 요약 시트 경고).
- 회계기준 변경, 사업결합, 중단영업이 있으면 차분값이 왜곡됩니다.
- 연결(CFS) 미작성 회사는 자동으로 별도(OFS)로 폴백하며, 요약 시트에 어느 쪽을 썼는지 표시됩니다.
- `.cache/` 에 API 응답을 저장해 재실행이 빠릅니다. 최신 데이터가 필요하면 폴더를 지우세요.
