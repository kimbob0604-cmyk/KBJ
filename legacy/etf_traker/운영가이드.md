# 굴리는 법 — GitHub Actions

> **봇 토큰은 누구에게도 주지 마세요.** AI 채팅창에도 넣지 마세요.
> 아래 3단계에서 깃허브에 직접 등록하시면 됩니다. 저장 후에는 화면에 다시 표시되지 않습니다.

깃허브가 **매일 아침 9시 10분에 대신 돌려줍니다.** 서버를 빌릴 필요도, PC를 켜둘 필요도
없습니다. 비용은 0원입니다.

전체 15분이면 끝납니다.

---

## 1단계 — 저장소 만들고 올리기 (5분)

깃허브 계정이 없으면 [github.com](https://github.com)에서 가입합니다. 무료입니다.

1. 우측 상단 **+** → **New repository**
2. 이름 아무거나 (`etf-tracker` 등)
3. **Private** 선택 ← 중요합니다
4. **Create repository**

압축 푼 폴더를 그 저장소에 올립니다. 두 가지 방법 중 편한 쪽으로:

**웹에서 드래그** — 방금 만든 저장소 화면의 `uploading an existing file` 링크를 누르고,
폴더 안의 파일을 전부 끌어다 놓은 뒤 **Commit changes**.

> 주의: `.github` 폴더는 점(.)으로 시작해서 맥 파인더에서 숨겨져 있습니다.
> 파인더에서 `Cmd + Shift + .` 를 누르면 보입니다. 이 폴더가 빠지면 자동 실행이 안 됩니다.

**터미널이 익숙하면**

```bash
cd etf_tracker
git init && git add -A && git commit -m "init"
git branch -M main
git remote add origin https://github.com/<내아이디>/etf-tracker.git
git push -u origin main
```

`.gitignore` 를 넣어 뒀으니 `.env` 나 `etf.db` 는 올라가지 않습니다.

---

## 2단계 — 텔레그램 봇 만들기 (5분)

**① 봇 토큰**

1. 텔레그램에서 **@BotFather** 검색 → 대화 시작
2. `/newbot` 전송
3. 봇 이름 입력 (아무거나, 예: `내 ETF 트래커`)
4. 봇 아이디 입력 (`_bot` 으로 끝나야 함, 예: `my_etf_tracker_bot`)
5. `1234567890:AAHxxxxxxxxxxxxx` 형태의 토큰을 줍니다 — **이걸 복사**

**② 내 대화방 ID**

1. 방금 만든 봇을 검색해서 **아무 메시지나 하나 보냅니다**
   ← 이걸 안 하면 봇이 나에게 말을 걸 수 없습니다. 꼭 하세요.
2. **@userinfobot** 검색 → `/start` 전송
3. `Id: 123456789` 숫자를 **복사**

---

## 3단계 — 깃허브에 토큰 등록 (2분)

저장소 → **Settings** → 왼쪽 메뉴 **Secrets and variables** → **Actions**

**New repository secret** 을 두 번 눌러 등록합니다.

| Name | Secret |
|---|---|
| `TELEGRAM_BOT_TOKEN` | BotFather가 준 토큰 |
| `TELEGRAM_CHAT_ID` | userinfobot이 준 숫자 |

이름은 **대문자로 정확히** 입력해야 합니다. 오타가 나면 실행이 실패합니다.

---

## 4단계 — 켜고 첫 실행 (3분 + 대기 10분)

1. 저장소 → **Actions** 탭
2. 노란 배너가 뜨면 **I understand my workflows, go ahead and enable them** 클릭
3. 왼쪽에서 **ETF 일일 트래킹** 선택
4. 오른쪽 **Run workflow** → 초록 버튼 **Run workflow**

첫 실행은 ETF 목록 구축과 1년치 시세 확보까지 하느라 **10~15분** 걸립니다.
이후엔 3~5분입니다.

실행 중인 작업을 클릭하면 진행 상황이 실시간으로 보입니다.
초록 체크가 뜨면 성공입니다.

> **첫날은 텔레그램 알림이 오지 않습니다.** 비교할 전날 데이터가 없어서입니다.
> 다음 영업일 아침부터 옵니다.

이제 끝났습니다. 평일 아침 9시 10분마다 자동으로 돕니다.

---

## 매일 무엇이 오는가

텔레그램으로 **두 개**가 옵니다.

**① 요약 메시지** — 30초 안에 훑는 용도

당일 상승·하락 TOP, 자금 유입·이탈, 거래 급증, 여러 ETF가 동시에 사고판 종목,
새로 편입된 종목까지 핵심만 추립니다. 레버리지·인버스는 요약에서 자동으로 뒤로 뺍니다.

**② 대시보드 HTML 파일** — 눌러서 여는 전체 화면

| 섹션 | 내용 |
|---|---|
| 당일 등락 | 상승·하락 TOP 10, 레버리지 숨기기 토글 |
| 기간별 수익률 | 1주·1개월·3개월·6개월·1년·YTD 탭 |
| 자금 유입·이탈 | 상장좌수 증감 × NAV 로 추정한 설정·환매 |
| 거래 급증 | 직전 20거래일 중앙값 대비 2배 이상 |
| ETF 구성종목 변동 | 새로 편입·제외된 종목, 여러 ETF가 동시에 움직인 종목 |
| 신규 상장 | 최근 60일 |
| 규모 | 순자산·거래대금 TOP |

파일을 누르면 브라우저에서 열립니다. 다크 모드도 지원합니다.

**왜 링크가 아니라 파일인가.** 비공개 저장소에서 GitHub Pages 로 웹 주소를 만들려면
유료 플랜이 필요합니다. 파일로 보내면 호스팅 없이 휴대폰·PC 어디서든 열립니다.

주소를 쓰고 싶으시면 — 저장소를 **Public 으로 바꾸거나** 유료 플랜인 경우:
Settings → Pages → Source 를 **GitHub Actions** 로 바꾸고,
Variables 에 `ENABLE_PAGES` = `true` 를 추가하면 고정 주소가 생기고
텔레그램 요약에 링크가 함께 붙습니다.

## 숫자를 어떻게 읽어야 하나

**제외된 종목의 `2 / 49개`** — 그 종목을 담고 있던 49개 ETF 중 2곳이 뺐다는 뜻입니다.
분모가 클수록 소수 운용사의 판단이라 의미가 있고, 분자와 분모가 같으면 아래를 보세요.

**`종목 사유로 빠진 건`** — 보유하던 ETF **전부**에서 같은 날 사라진 종목입니다.
거래정지·합병·분할 같은 기업 이벤트지 운용사가 판 게 아닙니다. 섞이면 항상 가장 큰
숫자가 가짜 시그널이 되므로 따로 뺐습니다.

**같은 종목이 비중확대·축소 양쪽에 나오는 경우** — 정상입니다. 액티브 ETF끼리
반대 방향으로 움직였다는 뜻이고, 그 자체가 읽을 거리입니다.

**자금 유입·이탈** — 공시된 설정·환매액이 아니라 상장좌수 증감으로 **추정**한 값입니다.
방향과 규모는 맞지만 정확한 금액은 다를 수 있습니다.

**기준일** — 항상 직전 완료 영업일입니다. 아침 9시에 도는 잡이라 당일 시세는
장중 값이고, 그걸 쓰면 등락률이 반쪽이 되기 때문입니다.

## 잘 되고 있는지 확인하는 법

### 수동으로 돌려보기

Actions 탭 → **ETF 일일 트래킹** → **Run workflow** 를 누르면
드롭다운에서 모드를 고를 수 있습니다.

| 모드 | 하는 일 |
|---|---|
| `run` | 평소와 같이 수집 → 비교 → 텔레그램 발송 |
| `run-nosend` | 발송 없이 로그로만 확인 (테스트용) |
| `verify` | 데이터 품질 10개 항목 검사 |
| `init` | ETF 목록 다시 구축 (신규 상장 반영) |

### 실패하면 알아서 알려줍니다

실행이 실패하면 **텔레그램으로 경고가 옵니다.**

```
⚠️ ETF 트래커 실행 실패 — 오늘 리포트가 생성되지 않았습니다.
로그: https://github.com/.../actions/runs/...
```

링크를 누르면 어디서 멈췄는지 로그가 보입니다. 조용히 묻히지 않습니다.

## 시작한 뒤 하실 일

### 매일

없습니다. 아침에 텔레그램만 보시면 됩니다.

### 며칠 뒤 — 알림량 조절

받아보시고 많다 싶으면 줄이세요.

저장소 → Settings → Secrets and variables → Actions → **Variables** 탭 →
**New repository variable**

| Name | Value | 결과 |
|---|---|---|
| `MIN_FUNDS` | `2` | 복수 ETF 동시 발생만. **130건 → 12건** |
| `ACTION_PP` | `3.0` | 비중변동 기준을 높여 알림 감소 |

Secrets가 아니라 **Variables 탭**입니다. 비밀이 아니니까요.

### 분기에 한 번 — 신규 ETF 반영

새로 상장된 ETF를 추적에 넣으려면 Actions → Run workflow → 모드 `init`.
기존 데이터는 지워지지 않습니다.

### 한 달에 한 번 — 품질 점검

운용사가 사이트를 개편하면 데이터가 조용히 틀어질 수 있습니다.
Actions → Run workflow → 모드 `verify` 로 10개 항목이 전부 PASS 인지 확인하세요.

### 60일마다 — 깃허브 알림 확인

**저장소에 아무 활동이 없으면 깃허브가 60일 후 스케줄을 자동으로 끕니다.**
끄기 전에 이메일로 알려주니, 그때 저장소에서 아무거나 한 번 커밋하거나
Actions에서 수동 실행 한 번 하면 다시 60일 연장됩니다.

이게 유일하게 신경 쓰셔야 할 부분입니다.

## 문제가 생기면

| 증상 | 원인과 해결 |
|---|---|
| Actions에서 빨간 X + 시크릿 오류 | 토큰 이름 오타. `TELEGRAM_BOT_TOKEN` 대문자 확인 |
| 실행은 성공인데 텔레그램이 안 옴 | 봇에게 먼저 말을 안 걸었을 가능성. 봇 찾아서 아무 메시지나 전송 후 재실행 |
| 첫날 알림 없음 | 정상입니다. 이틀치가 쌓여야 비교가 됩니다 |
| 알림이 수백 건 | 지수 정기변경일(3·6·9·12월 두 번째 목요일) 가능성. 정상입니다 |
| 특정 운용사가 통째로 빠짐 | `verify` 모드 실행 → [1][2] 항목 확인. 사이트 개편이면 어댑터 수정 필요 |
| 스케줄이 안 돎 | 저장소 60일 무활동으로 비활성화됐을 가능성. Actions 탭에서 다시 Enable |

## 리서치할 때는 로컬에서

텔레그램 리포트를 보다가 특정 테마를 파고들고 싶으면, PC에 받아서 조회하시면 됩니다.
(GitHub Actions는 자동 발송용이고, 대화형 조회는 로컬이 편합니다.)

```bash
pip install -r requirements.txt
python tracker.py --themes            # 어떤 테마가 있는지
python tracker.py --research 조선      # 조선 테마 심층 조회
python tracker.py --research 바이오헬스
```

`--research` 는 해당 테마의 ETF 목록, 운용사별로 무엇을 얼마나 바꿨는지,
복수 ETF에서 동시 발생한 종목까지 보여줍니다.

DB는 Actions 실행 결과에서 받을 수 있습니다 —
Actions → 최근 실행 클릭 → 하단 **Artifacts** → `etf-db-...` 다운로드 →
압축 풀어서 폴더에 `etf.db` 로 두면 됩니다.

## 참고 — 다른 실행 방법

GitHub Actions 대신 다른 곳에서 굴리고 싶으실 때를 위해 남겨둡니다.

### 내 PC

가장 간단하지만 **PC가 꺼져 있거나 절전이면 그날은 건너뜁니다.**

```bash
cd etf_tracker
pip install -r requirements.txt
cp .env.example .env       # 편집기로 열어 토큰 두 줄 채우기
python tracker.py --check  # 연결 확인
python tracker.py --init   # 최초 1회
```

맥/리눅스 자동 실행 — `crontab -e` 후:

```cron
10 9 * * 1-5  /전체/경로/etf_tracker/run.sh >> /전체/경로/etf_tracker/log.txt 2>&1
```

윈도우 — 작업 스케줄러에서 트리거 평일 09:10, 동작 `python`,
인수 `tracker.py --run`, 시작 위치를 `etf_tracker` 폴더로 지정.

### 클라우드 서버 (VPS)

월 5천~1만원. 24시간 안정적이지만 리눅스 기본 명령어를 다룰 수 있어야 합니다.
메모리 512MB짜리 가장 낮은 사양이면 충분합니다. 접속 후 위 "내 PC"와 동일하게
설치하고 cron만 걸면 됩니다.

## 왜 아침 9시 10분인가

운용사마다 PDF 갱신 시각이 다릅니다. 실측에서 **오전 8시 기준으로는 403개 중 183개가
아직 전일 데이터**였습니다. 시스템은 정직하게 전일 날짜로 저장하므로 데이터가 틀어지진
않지만, 그만큼 리포트가 하루씩 밀립니다.

9시 10분이면 대부분 갱신이 끝나 있고, 장 시작(09:00) 직후라 그날 판단에 바로 쓸 수 있습니다.

시간을 바꾸려면 `.github/workflows/daily.yml` 의 `cron: '10 0 * * 1-5'` 를 고치세요.
깃허브는 UTC 기준이라 **한국시간에서 9시간을 뺍니다** (한국 09:10 = UTC 00:10).
