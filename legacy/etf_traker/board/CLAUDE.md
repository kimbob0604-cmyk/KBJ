# CLAUDE.md

국장 마감 보드. 매 영업일 18:00에 신고가·섹터 리포트를 자동 생성한다.

---

## 0. 이 파일을 읽는 법

- 여기 적힌 정의는 임의로 바꾸지 않는다. 바꿔야 하면 `DECISIONS.md`에 근거를 적고 이 파일을 함께 수정한다.
- `## 9. 미확정`에 있는 항목은 아직 답이 없다. 이 항목에 대해 코드를 쓸 때는 추측하지 말고 사용자에게 묻는다.
- 새 기능 아이디어는 구현하지 말고 `BACKLOG.md`에 한 줄로 적는다.

---

## 1. 목적

사용자(버이사이드 리서치)가 매일 손으로 쓰던 마감 코멘트를 대체한다. 최종 산출물은 두 개다.

1. 웹 대시보드 — 신고가 보드, 섹터 등락률, 히트맵, 섹터 뉴스
2. 18:00 텔레그램·노션 리포트 — 지수·수급 → 테마별 반응 → 이벤트 리뷰/프리뷰

**완전 무인화가 목표가 아니다.** 17:15에 초안을 사용자에게 보내고, 35분 검수 후 18:00 발송한다. 사용자의 작성 시간을 줄이는 것이 목표다.

레퍼런스 산출물은 `docs/reference-comment.md`에 있다. 이 수준·문체를 기준으로 삼는다.

미국장은 **별도 보드**다(`board/us/`, `docs/US.md`). 이 문서의 정의·규칙을 그대로
따르되 산출물은 간밤 미국장 브리프 한 장과 화면 하나이고, 국장 리포트에 섞지 않는다.

---

## 2. 절대 규칙

이 규칙을 어긴 코드는 머지하지 않는다.

1. **추정을 단정하지 않는다.** 계산되지 않은 값은 출력하지 않는다. 추정치를 쓸 수밖에 없으면 필드에 `is_estimate: true`를 달고 리포트에 "추정"으로 표기한다.
2. **모든 수치는 출처 필드를 갖는다.** `source`(pykrx / KRX / DART / 뉴스URL)와 `as_of` 타임스탬프 없이 저장하지 않는다.
3. **LLM에 숫자를 계산시키지 않는다.** 모든 판정·집계는 코드가 하고, LLM은 이미 계산된 사실을 서술만 한다.
4. **LLM이 종목명·수치를 지어내면 실패로 처리한다.** 서술 생성 후 리포트에 등장한 모든 종목명이 입력 컨텍스트에 있었는지 검증하는 후처리를 반드시 통과시킨다.
5. **신뢰도 0.7 미만 테마 매핑은 서술 프롬프트에 넣지 않는다.**
6. **에러를 삼키지 않는다.** 데이터 소스 실패 시 부분 리포트를 내되, 리포트 상단에 무엇이 빠졌는지 명시한다.

## 4. 용어 정의 (고정)

| 용어 | 정의 |
|---|---|
| 60일 신고가 | 직전 60영업일(당일 제외) 최고가를 당일 갱신 |
| 52주 신고가 | 직전 252영업일(당일 제외) 최고가를 당일 갱신 |
| 역사적 신고가 | 상장 이후 전체 최고가를 당일 갱신 |
| **종가** | **KRX 정규장 종가.** NXT 애프터마켓·시간외 단일가는 종가가 아니다 (D-080) |
| 종가 기준 / 고가 기준 | 둘 다 계산해 별도 컬럼으로 저장. **리포트 기본값은 종가 기준** (고가 기준은 장중에 잠깐 뚫고 종가는 하락 마감한 날도 신고가로 잡아, '일간 마이너스인데 신고가' 가 된다). 화면 토글로 고가 기준도 볼 수 있다 |
| 라벨 우선순위 | 역사적 > 52주 > 60일. 상위가 하위를 포함 |
| 신규 / 이어감 | 직전 영업일에 같은 라벨이 없었으면 신규, 있었으면 이어감 |
| 갭 | (기준 최고가 − 현재가) / 기준 최고가. 3종 각각 계산 |
| 보드 하한 | 시가총액 1,000억 이상. **화면 필터가 아니라 생성 단계**에서 걸어 엑셀·텔레그램도 같은 목록을 쓴다 (D-072) |
| 근접 | 갭 5% 이내 + 시총 1,000억 이상 (설정으로 조정. D-072 이전 기본값은 200억) |
| 5일 축소폭 | 현재 갭 − 5영업일 전 갭. **음수일수록 빠르게 좁혀짐** |
| 저항두께 | 현재가~기준 최고가 구간의 누적 거래량 ÷ 20일 평균 거래량 |
| 거래량 배수 | 당일 거래량 ÷ 20일 평균 거래량 |
| 브레드스 | 업종 내 상승 / 보합 / 하락 종목수 |
| 재료 반납 | (고가 − 종가) / (고가 − 전일종가) ≥ 0.7 |

역사적 신고가는 종목별 사상 최고가와 기록일을 스칼라로 저장하고 매일 당일 고가와 비교해 갱신한다. 전체 일봉을 매일 재계산하지 않는다.

### 구현하며 확정한 세부 (근거는 `docs/DECISIONS.md`)

| 항목 | 확정 | 근거 |
|---|---|---|
| 역사적 최고가 스칼라 | `hi`(당일 포함)와 `prev_hi`(직전일까지)를 함께 저장. 판정에는 `prev_hi` 를 쓴다 | D-008 |
| 저항두께 구간 판정 | 종가 기준. 룩백 창은 해당 라벨의 창 | D-005 |
| 거래량 배수의 20일 평균 | 당일 제외, 직전 20영업일 | D-006 |
| 근접 라벨 | 임계 안에 드는 것 중 가장 상위(역사적 > 52주 > 60일) 하나 | D-007 |
| 수정주가 미반영 시계열 | 하루 ±31% 초과 점프를 감지해 역사적 판정 제외 + 룩백 창을 점프 이후로 절단 | D-001 |
| 당일 종가의 출처 | KRX 오픈API `stk_bydd_trd` 확정치로 당일 봉을 덮는다. 못 받은 날은 네이버 값을 쓰되 보드에 '종가 잠정' 을 띄운다 | D-080 |
| 업종·테마 등락률 | 업종 지수가 아니라 구성종목 시가총액 가중 평균(계산값) | D-004 |

## 5. 분류 체계

**1층 자체 섹터 48개** (`knowledge/sectors.yaml`) — 전 종목이 하나씩 배정된다. 커버리지 보장용.
KRX 업종 14개로는 랭킹 표의 해상도가 안 나온다(비철금속과 철강이 둘 다 '철강금속'이다).
KRX 업종은 버리지 않고 배치 분류의 후보를 좁히는 사전 필터(`krx_hint`)로 쓴다.
근거는 `docs/DECISIONS.md` D-014.
**2층 자체 테마** — `knowledge/themes.yaml`. 다대다. 해상도 담당.

에프엔가이드·WICS 섹터분류는 **사용하지 않는다**(사용 불가로 확정).

매핑되지 않은 종목은 `미분류` 버킷에 넣고 일간 리포트에 종목수를 노출한다. 신고가나 거래량 이상으로 처음 올라온 미분류 종목은 그때 수동 검수한다.

### 축 유형

테마마다 축 유형이 있고, 탐지기가 이 값으로 분기한다. 전체 정의는 `themes.yaml`의 `axes` 참조.

`project_chain` · `supply_chain` · `development_stage` · `channel_brand` · `regulated_yield` · `cycle_spread` · `platform_ip` · `order_downstream`

`regulated_yield`는 단계가 없다. 밸류체인 확산 탐지기를 끄고 정책·금리 매칭으로 대체한다.

## 6. 탐지기

모두 결정론적이다. 출력은 `events.json`의 이벤트 배열이며, 각 이벤트는 `type`, `theme`, `tickers`, `evidence`(계산된 수치), `severity`를 갖는다.

| # | 이름 | 판정 |
|---|---|---|
| 1 | valuechain_diffusion | 오늘 반응 단계 집합 − 어제 반응 단계 집합. 신규 진입 단계 반환 |
| 2 | opposite_reaction | 같은 뉴스 클러스터에 연결된 두 테마의 등락 부호가 반대 |
| 3 | material_giveback | 재료 반납 조건 충족 + 당일 등락률 3% 미만 |
| 4 | volume_anomaly | 거래량 배수 5배 이상 |
| 5 | flow_alignment | 기관·외국인 동시 순매수 상위 |
| 6 | multi_label_high | 60일·252일·역사적 중 2종 이상 동시 돌파 = **52주 이상**. 라벨이 중첩이라 이 숫자는 '몇 종'이 아니라 '어느 등급 이상'을 고른다 (D-073) |
| 7 | claim_check | 전일 `claims.json`의 주장을 당일 성과와 대조. 유지 / 반증 / 보류 |
| 8 | sector_rotation | 전일 상위 5업종과 당일 상위 5업종의 교집합 크기 |
| 9 | proximity_cluster | 한 테마에서 근접 종목 3개 이상 |
| 10 | breakout_fail | 어제 근접이었으나 오늘 갭이 다시 벌어진 종목 |

탐지기 1은 축 유형이 `development_stage`이면 단계 확산 대신 모달리티 확산으로 판정한다.

## 7. 서술 생성

`events.json` + 테마 컨텍스트 + 전일 `claims.json`을 넣고 섹터별로 병렬 호출한다.

- 서술 대상은 스코어 상위 4~6개 테마만. 나머지는 수치 테이블로만 나간다.
- 강제 포함: 전일 주장이 있는 테마, 당일 대형 이벤트가 있는 테마.
- 스코어 = 업종 등락률 z-score + 신고가 종목수 + 거래대금 증가율 + 신규 진입 단계 수 + 수급 일치 여부. 가중치는 `config/score.yaml`.

### 모델 배분

| 용도 | 모델 | 비고 |
|---|---|---|
| 뉴스 클러스터링·테마 매칭 | `claude-haiku-4-5-20251001` | Batch API |
| 종목 부트스트랩 분류 | `claude-haiku-4-5-20251001` | Batch API, 1회성 |
| 섹터 서술·장마감 총평 | `claude-sonnet-5` | 실시간 |

Batch API는 입출력 50% 할인. 프롬프트 캐시 히트는 입력가의 10%. `themes.yaml`과 문체 규칙은 매일 동일한 접두사이므로 반드시 캐시 대상 접두사에 넣는다.

### 문체 규칙

- `~함` 종결. 명사형 종결 허용.
- 종목 언급 시 등락률과 거래대금을 함께 적는다.
- 수치는 원문 그대로. 반올림해서 바꾸지 않는다.
- 추정·전망은 "추정", "전망"을 명시한다.
- 단독 보도나 미확인 루머가 트리거면 그 사실을 함께 적는다. ("재료는 미확인 루머 — X 포워딩의 지분 인수설" 은 트리거를 적은 문장이다)
- **트리거를 모르면 트리거 문장을 쓰지 않는다.** "트리거는 확인되지 않음"·"미확인"(뒤에 루머·보도·~설 이 이어지지 않는 것)·"뉴스 없음"·"단정하긴 어려움" 류는 금지 — 등락률·신고가·거래량 사실만 적는다. 프롬프트로만 막지 않고 `writer/verify.py` 가 기계로 막는다 (D-085).
- 문장에 형용사를 붙여 강조하지 않는다. 수치가 강조를 대신한다.

```
17:00  writer — 섹터별 병렬 서술
17:15  초안을 사용자에게 발송
17:15~17:50  사용자 검수
       같은 실행 끝에서 텔레그램 발송 — 일간 코멘트 → 랭킹 요약(52주 이상
       신고가 + 종목별 수급 + 섹터) → 보드 HTML·랭킹 엑셀 (D-063)
18:00  최종 발송 + claims.json 저장
```

파일 발송은 **보드를 만든 그 실행이 이어서 한다**. 예전에는 17:30 크론으로
떼어 놨는데, 예약 실행이 큐라서 두 번 기다렸고 앞 실행이 아직 커밋을 못 했으면
발송 쪽이 낡은 보드를 보고 조용히 건너뛰었다.

**GitHub 크론은 제때를 보장하지 않는다.** 정시(:00)와 :10 · :30 에 전 세계가
몰려 그 시간대가 가장 많이 밀린다 — 이 레포의 `10 7`(16:10 KST) 크론이 실제로
12:1x UTC 에 깨어났다(다섯 시간). 그래서 분을 붐비지 않는 자리(`7 7`)로 옮기고,
못 보낸 날을 위한 재시도 크론을 두 번 더 걸었다. 재시도는 `--once` 로 이미 보낸
기준일이면 아무 일도 하지 않는다(표식은 `docs/api/sent.json`).

분 단위로 정확해야 하면 크론이 아니라 밖에서 깨운다 — 워크플로가
`repository_dispatch`(`board-daily` · `board-send`)를 받는다. 무료 스케줄러가
`POST /repos/:owner/:repo/dispatches` 를 부르면 그 시각에 바로 돈다.

휴장일에는 기준일이 오늘이 아니므로 스스로 생략한다(`--only-fresh`).

`/daily` 슬래시 커맨드가 16:07~17:15 구간을 한 번에 돌린다.

## 9. 미확정

이 항목은 답이 없다. 관련 코드를 쓰기 전에 사용자에게 묻는다.

1. ~~**수정주가 처리**~~ → **확정 (D-056)**. 네이버 siseJson 이 수정주가다(대조군 삼성전자가 두 소스 1,635일 전부 일치). 의심 12종목 중 5종목은 공시로 확인된 감자·병합·무상증자라 가드가 맞았고, 5종목은 증분 적재가 남긴 낡은 과거 구간 때문이라 `refresh_suspects()` 가 다시 받아 덮는다. 2종목(007610 · 520101)이 보류였는데 `520101` 은 정체가 밝혀졌다 — '미래에셋 레버리지 SK하이닉스 단일종목ETN' 이고, ETN 필터가 낱말 경계 때문에 놓치고 있었다(D-065). 이제 유니버스에서 빠진다. `007610`(선도전기)만 보류로 남았다 — 사유는 D-056.
2. **KIS 시장 전체 수급이 0 으로 온다 — 파라미터 문제가 아니다 (D-081 에서 닫음).** 2026-09-17 실측 네 번으로 세 축을 전부 흔들어 봤다. `FID_COND_MRKT_DIV_CODE` 는 'U' 확정('J' 는 rt_cd=2 INVALID), 날짜 파라미터는 무시되며(어느 구간이든 같은 300행), `FID_INPUT_ISCD`/`_1`/`_2` 24조합이 **전부 rt_cd=0 · 300행 · 순매수 칼럼 전부 0** 이다. 지수 시세(`bstp_nmix_prpr` = 6715.41)는 그날 코스피 종가와 일치하고 필드 이름(`prsn`·`frgn`·`orgn_ntby_tr_pbmn`)도 응답에 실제로 있다 — 주체별 칼럼 30개가 다 있는데 그 30개가 300행 전부 0 이다. **코드로 더 좁힐 곳이 없다.** 같은 앱키로 종목별 수급은 실제 숫자를 주므로, 남은 것은 KIS 쪽 권한·서비스 신청이거나 다른 소스다(네이버 폴백은 HTTP 410 로 없어졌다). **네이버 폴백도 HTTP 410 으로 없어져 새 주소로 옮겼다(D-082)** — `m.stock.naver.com/api/index/{시장}/integration` 의 `dealTrendInfo`. 다만 구분이 **개인·외국인·기관계 셋뿐이고 기타법인은 안 온다**. 역산하지 않고 집계 범위 배너에 사유를 적는다. 사용자가 확인할 것은 하나다 — **KIS 에 시장별 투자자매매동향이 개인 앱키(custtype=P)에 열려 있는지, 별도 신청이 필요한지.** 열리면 기타법인까지 되찾는다. 진단기는 `--kis-probe` 로 남겨 뒀다. **종목별** 수급에도 네이버 폴백이 생겼다 — KIS 가 23시 전후 접속 자체가 안 되는 시간대가 있어(D-083, 원인은 추정) 첫 접속 실패에서 멈추고 `trend` 의 순매매량(주)으로 채운다 — 개인은 응답에 없는 날이 있어, 없으면 만들지 않는다.
3. **뉴스 클러스터링·테마 매칭 (LLM)** — 수집기는 붙였다(D-044). 지금은 테마명·대표종목명으로 질의해 그 테마에 매다는 결정론적 방식이라, 6장 탐지기 2(opposite_reaction)가 요구하는 '같은 뉴스 클러스터'가 아직 없다. 7장의 Haiku Batch 클러스터링을 붙여야 한다. 저작권은 링크·헤드라인·요약만 보관하는 것으로 정리했고 원문은 저장하지 않는다.
4. **`cycle_spread` 외부 지수** — SCFI, BDI, 정제마진 등의 데이터 소스 미확보.
5. **임상 단계 데이터 소스** — `development_stage` 테마용. 공시 기반 수동 갱신 가능성.
6. **`themes.yaml` seeds 검수** — 비상장사가 섞여 있다(세메스, 삼성디스플레이, SK온, 토스뱅크는 비상장, 앰코는 국내 미상장). 상장 마스터와 대조해 거르는 코드는 넣었다(`engine/themes.py`). **미해결의 정체는 대부분 사명 변경이다**(엔씨소프트 → NC, LIG넥스원 → LIG디펜스앤에어로스페이스). 마스터가 증명한 7건은 `renames:` 표로 붙였고(D-066), **20건이 남아 있다** — 옛 이름이 마스터에도 저장소에도 없어 자동으로는 못 푼다. `python3 -m board.run --diagnose-banner` 로 목록과 후보를 뽑고, 이름별로 `renames:`(사명 변경) 나 `unlisted:`(상장폐지·비상장) 에 사유와 함께 적는다. **확신이 없으면 두는 쪽이 맞다** — 틀린 매핑은 빈칸보다 나쁘다.

   - 미확정으로 남은 것은 네이버 금융 종목 뉴스 비공식 URL 의 채택 여부(`--trigger-probe` 가 HTTP 200 JSON 으로 기록했다)와 `XDIGEST.md` 8장 12번(계정 인사이트 구획을 뺄지 다른 대상으로 바꿀지)이다.

## 10. 확인된 사실

추측하지 말고 이 값을 쓴다.

- pykrx는 종목별 투자자 구분 순매수거래대금을 제공하며, 투자자 구분에 기타법인이 포함된다.
- pykrx는 네이버·KRX 스크래핑 기반이라 사이트 개편 시 깨진다. 폴백 소스를 둔다.
- 트레이딩뷰 히트맵은 크기 기준(시총·거래량·가격×거래량·모노 사이즈), 색상 기준(기간별 등락률 등), 그룹핑(섹터별·그룹 없음)의 세 컨트롤로 구성된다.
- 인베스팅닷컴 52주 신고가 근접 스크리너의 기본값은 갭 -5% 이내, 시총 200억원 이상이다. 우리도 여기서 시작했으나 시총 하한은 사용자 요청으로 1,000억으로 올렸다(D-072).
- 콕스톡은 250일내 고가 기준을 쓴다. 우리는 252영업일을 쓰므로 결과가 다를 수 있다.
- 국내 색상 관례는 상승 적색, 하락 청색. 트레이딩뷰와 반대다.
