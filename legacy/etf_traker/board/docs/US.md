# 미국장 신고가 보드

간밤 미국장의 신고가·등락 흐름을 한 장으로 낸다. 국장 보드(`board/`)와 **정의를
공유하고 데이터·화면은 나눈다**. 결정 근거는 `DECISIONS.md` D-076.

산출물은 둘이다.

1. **브리프 텍스트** — ①~⑧ + 신고가 전 종목. 텔레그램·노션에 그대로 붙인다
2. **웹 화면** — `docs/us/index.html`. 외부 의존 없는 단일 HTML

---

## 빠르게

```bash
python3 -m board.run --us-demo     # 합성 데이터로 끝까지 (네트워크 불필요)
python3 -m board.run --us-check    # 소스가 살아 있는지
python3 -m board.run --us-init     # 최초 1회. 유니버스 전 종목 2년 일봉 (20~40분)
python3 -m board.run --us-daily    # 매일. 수집 → 집계 → 브리프 → 화면
python3 -m board.run --us-build    # 수집 없이 집계만 다시
python3 -m board.run --us-brief    # state 만 읽어 브리프를 다시 출력
python3 -m board.run --us-send     # 브리프를 텔레그램으로 (files 면 화면 HTML 도 첨부)
```

자동 실행은 `.github/workflows/us-board.yml`. 평일 22:00 UTC(= 07:00 KST 이튿날)에
돌고, 브리프를 런 페이지 요약에 그대로 찍는다.

| 환경변수 | 기본값 | 용도 |
|---|---|---|
| `US_DB` | `board/us_board.db` | sqlite 파일 |
| `US_OUT` | `docs/us/index.html` | 화면 출력 |

## 소스

키가 필요 없다. 국장과 달리 `.env` 를 채우지 않아도 돈다.

| 무엇 | 소스 | 비고 |
|---|---|---|
| 유니버스·시총·섹터·산업 | 나스닥 스크리너 `api.nasdaq.com/api/screener/stocks` | 한 번에 전 종목 |
| 일봉 | 나스닥 히스토리 `api.nasdaq.com/api/quote/{sym}/historical` | **러너 실측으로 여기로 왔다** (D-077) |

러너에서 stooq 는 HTTP 200 에 본문이 비어 오고, yahoo 는 429 다. 두 어댑터는
폴백으로 남아 있고 워크플로가 점검 결과를 보고 `nasdaq → stooq → yahoo` 순으로
**되는 것**을 골라 `US_HISTORY` 로 넘긴다. 설정 파일은 건드리지 않는다.

### 소스가 막혔을 때

`--us-check` 가 FAIL 을 내면 순서대로 본다.

1. **HTTP 403 · CONNECT 403** — 사내망·프록시 정책. 개발 환경에서는 대개 이것이다.
   판정·화면은 `--us-demo` 로 확인할 수 있다.
2. **스크리너가 0행** — 응답 형식이 바뀐 것이다. `sources.parse_screener` 의
   `data.rows` 경로를 확인한다. 0행이면 예외를 올린다 — 빈 보드를 내지 않는다.
3. **stooq 가 'Exceeded the daily hits limit'** — 하루 한도다. `sources.history: yahoo`
   로 바꿔 그날은 야후로 받는다.

## 정의

국장과 같은 것(`CLAUDE.md` 4장)은 다시 적지 않는다. 미국장에만 있는 것만 적는다.

| 용어 | 정의 |
|---|---|
| 신고가 | 직전 60거래일(당일 제외) 최고가를 당일 갱신 |
| 52주 신고가 | 직전 252거래일(당일 제외) 최고가를 당일 갱신. 신고가에 **포함된다** |
| 52주 신저가 | 직전 252거래일(당일 제외) 최저가를 당일 하회 |
| 연속 신고가 | 기준일부터 거슬러 신고가 라벨이 끊기지 않은 거래일 수 |
| 52주 첫 진입 | 최근 5거래일 안에 52주 라벨이 처음 뜬 종목. **저장된 일봉 구간 안에서만** |
| 거래대금 | 종가 × 거래량 **추정치**. 실 거래대금이 아니다 (`turnover_is_estimate`) |
| 거래대금 배수 | 당일 거래대금 ÷ 직전 20거래일 평균 |
| 유니버스 | 시총 $500M↑ · 거래대금 $30M↑ · 주가 $5↑. **화면 필터가 아니라 생성 단계**에서 건다 |
| 기준일 | 달력이 아니라 **받은 일봉**이 정한다 — 종목별 마지막 봉 날짜의 최빈값 |

**역사적 신고가는 없다.** 무료 소스가 상장 이후 전 구간을 주지 않는다 (D-076).

### 섹터

나스닥 스크리너의 `industry`(150개 남짓)를 규칙으로 묶어 자체 섹터 17개를 만든다.
규칙은 `board/us/knowledge/us_sectors.yaml`, 종목별 손수정은 `us_overrides.yaml`.
매칭 순서는 **손수정 → industry 규칙 → sector 폴백 → 회사 이름**이고, 어디서
왔는지는 각 행의 `sector_src`(`override`/`industry`/`sector`/`name`)에 남는다.

이름을 마지막에 보는 이유는 실데이터다 — 스크리너는 적지 않은 종목의 섹터·산업을
**비워서** 보낸다(D-078). 이름은 약한 신호라 순서가 마지막이고, `Technologies`·
`Holdings` 처럼 업종을 안 가리는 낱말은 규칙에 넣지 않는다. 여기서도 안 풀리면
`미분류` 로 두고 그 수를 배너에 올린다 — 소스 공란과 규칙 미매치를 갈라서 적는다.
미분류로 남은 원본 문자열은 매일 `state_us/*/unmapped.json` 에 쌓인다.

⑧이 쓰는 2층 산업 라벨(Cybersecurity · Memory & Storage · Semi Cap Equipment 등)은
스크리너 industry 로는 안 갈려서 `us_overrides.yaml` 에 종목별로 적는다.
**확신이 없으면 비워 두는 쪽이 맞다** — 틀린 매핑은 빈칸보다 나쁘다.

## 구조

```
board/us/
  sources.py    나스닥 스크리너 · stooq · yahoo 어댑터 + 파서
  pipeline.py   소스 → DB (init / daily)
  db.py         sqlite. px · snap · label · lowlabel
  sectors.py    industry → 자체 섹터 (규칙 기반. LLM 을 부르지 않는다)
  engine.py     지표·집계. 신고가 판정은 board/engine/newhigh.py 를 쓴다
  build.py      DB → state_us/YYYYMMDD/{universe,board}.json
  brief.py      board.json → ①~⑧ 텍스트
  render.py     board.json → 단일 HTML
  demo.py       합성 데이터 (네트워크 불필요)
  knowledge/    us_sectors.yaml · us_overrides.yaml
```

단계 사이는 **파일로만** 넘어간다. `brief.py` 와 `render.py` 는 DB 를 모르고,
board.json 에 없는 값은 화면에도 브리프에도 없다.

## 브리프가 읽는 자리

| 절 | 무엇 | board.json |
|---|---|---|
| ① 한눈에 | 신고가 수·전일 대비, 52주 고/저, 상승·하락, ±5%, $100B+ | `summary` |
| ② 5일 흐름 | 신고가·52주고·52주저·상승비·중앙값 | `trend` |
| ③ 섹터 로테이션 | 섹터별 신고가 수 추이 → 오늘, 당일·5일 중앙 등락 | `sectors` |
| ④ 등락 온도 | 시총 구간별 중앙 등락·상승 비율 | `tiers` |
| ⑤ 대형주 | $100B+ 상승·하락 상위 | `mega` |
| ⑥ 연속·신규 | 연속 신고가, 52주 첫 진입 | `streaks` · `fresh52` |
| ⑦ 52주 대장 | 거래대금 순 | `leaders` |
| ⑧ 등락 상위 | 산업 묶음 ($2B+) | `movers` |
| 📋 전 종목 | 섹터별 티커 | `universe.json` |

②의 추이는 저장된 라벨이 아니라 **일봉에서 그날그날 다시 판정해** 만든다. 처음 돌린
날에도 5일이 채워진다. 다만 유니버스는 기준일 하나다 — 과거 날짜의 시총·거래대금을
따로 들고 있지 않아 그날의 유니버스를 복원하지 않는다. 그 사실이 `trend_note` 에 있다.

## 시스템 조합 탐색 (`--us-search`)

국장 `docs/SIGNALS.md` 12장과 **같은 방법·같은 기준**을 미국 일봉에 건다
(`us/btsearch.py`, 설정 `config/us.yaml` `backtest`·`search`). 수동 워크플로
`us-search.yml` 로만 돈다.

- 조합 44개 = 국장 격자 18 + 원문 시스템 넷(쿠퍼·라쉬키·볼린저 수축·이격도) × SPY 200일선 게이트 유무
- 최근 250영업일 봉인 → 그 앞 탐색 구간의 전체·앞 절반·뒤 절반 모두
  거래 200↑ · 승률 55%↑ · 평균>0 · PF 1.2↑ → 후보만 봉인 구간에서 한 번 판정
- 대상은 **오늘** 시총 $300M↑ 현재 상장 종목이다 — 폐지 종목이 없고 과거에 작던
  종목이 들어와 결과가 좋게 잡힌다. 채택되더라도 이 편향을 먼저 의심한다
- 비용: 매도 0.15%(국내 증권사 수수료 두 번) + 편도 슬리피지 0.1%. 환전 비용 제외
