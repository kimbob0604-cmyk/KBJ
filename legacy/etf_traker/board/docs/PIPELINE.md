# 파이프라인 설계 — 무엇을 어디로 보내고, 어디에 LLM 을 쓰는가

## 1. 멀티에이전트를 어디에 쓰는가

결론부터: **랭킹 표에는 안 쓴다.** 정렬하고 세고 나누는 일이라 코드가 한다.
LLM 을 넣으면 느리고 비싸고 무엇보다 **틀린다** — CLAUDE.md 2장 3번이 금지한 바로 그것이다.
2,800종목 × 5기간 수익률을 모델에 시키면 하루 몇 달러를 태우고 매일 다른 숫자가 나온다.

LLM 병렬이 실제로 값어치 있는 자리는 셋뿐이고, 성질이 서로 다르다.

| 자리 | 왜 LLM 이 필요한가 | 병렬 방식 | 빈도 | 모델 |
|---|---|---|---|---|
| **종목 → 섹터 배정**<br>`classify/sectors.py` | 2,800종목을 48섹터에. 항목마다 독립이고 판단이 필요하다 | **Batch API** — 25종목씩 112요청. 입출력 50% 할인 | 최초 1회 + 신규 상장 | haiku-4-5 |
| **뉴스 클러스터링·테마 매칭** | 기사 수백 건을 사건 단위로 묶고 테마에 붙인다 | Batch API | 매일 1회 | haiku-4-5 |
| **섹터 서술**<br>`writer/compose.py` | 이미 계산된 사실을 문장으로 잇는다 | **실시간 병렬** — 섹터당 1회, 4개 동시 | 매일 4~6회 | sonnet-5 |

세 자리 모두 **같은 접두사를 공유**한다(섹터 사전 / 테마 사전 / 문체 규칙).
접두사에 `cache_control` 을 걸어 두면 첫 호출 이후는 입력가의 10%다.
접두사에 날짜나 실행 시각을 섞으면 캐시가 매일 깨진다 — 절대 넣지 마라.

### 배치 vs 실시간

| | Batch API | 실시간 |
|---|---|---|
| 가격 | 50% 할인 | 정가 |
| 지연 | 대부분 1시간, 최대 24시간 | 초 단위 |
| 쓸 곳 | 전 종목 분류, 뉴스 클러스터링 | 서술, 신규 상장 몇 개 |

18시 발송이 마감이라 **서술은 배치를 쓸 수 없다.** 분류는 하루 늦어도 되니 배치다.

### 섹터 분류 비용 (실측 아님, 추정)

2,800종목 / 25 = 112요청. 접두사 약 1,500토큰(캐시), 요청당 본문 약 800토큰,
출력 약 1,500토큰. haiku-4-5 배치가 (입력 $0.5 / 출력 $2.5 per MTok) 이므로
대략 **$0.5 안팎**. 1회성이라 신경 쓸 규모가 아니다.

## 2. 무엇을 어디로 보내는가

같은 `rankings.json` 을 셋이 읽는다. **표를 통째로 세 번 보내는 게 아니라
매체가 잘하는 것만 준다.**

| | 엑셀 | 대시보드 | 텔레그램 |
|---|---|---|---|
| 용도 | 사장님이 직접 가공 | 탐색·확인 | 알림 |
| 보는 시간 | 몇 분 | 몇십 초 | **3초** |
| 섹터 표 | 48섹터 전부 × 2기간 | 48섹터 전부, 기간 토글 | **상위 5 · 하위 3** |
| 종목 표 | 30행 × 2표 | 30행 × 2표, 교집합 강조 | **교집합만** |
| 신고가 | — | 달성 + 근접 전체 | 역사적·52주만 |
| 히트맵 | — | 크기·색·그룹 컨트롤 | — |
| 일간 코멘트 | — | 전문 | **전문** + 링크 (D-084) |
| 정렬·필터 | 엑셀 기능 | 열 클릭 | — |

일간 코멘트만 예외다. 17:15 초안은 알림이 아니라 **검수 대상**이라 텔레그램에도
문단·표를 고르지 않고 전부 보낸다 — 여기서 추리면 검수를 건너뛴 채 18:00 에 나간다.
표는 모바일에서 읽히지 않으니 행마다 한 줄로 푼다 (D-084).

### 텔레그램이 전체 표보다 나을 수 있는 유일한 지점

**교집합.** 수익률 상위 30 ∩ 거래량 3일/1달 상위 30.

수익률만 높으면 이미 지나간 것일 수 있고, 거래량만 튀면 하루짜리일 수 있다.
둘이 겹치는 종목은 **오르면서 거래가 며칠째 붙어 있는 것**이라 성질이 다르다.
이 교집합은 보통 하루 5~20종목이고, 그게 딱 모바일 한 화면이다.

전체 랭킹을 텔레그램으로 보내면 스크롤 세 번에 아무도 안 읽는다.

### 거래량 3일/1달을 쓰는 이유

`거래량 배수`(당일 / 20일 평균)와 다르다. 배수는 하루짜리 튐에도 크게 뛴다.
`3일/1달`은 사흘 평균이라 **며칠째 붙어 있는지**를 본다. 하루만 터진 종목은
희석돼서 덜 오르고, 사흘 연속이면 크게 오른다. 교집합의 다른 축으로 이게 맞다.

## 3. 하루 실행 순서

```
15:30  장 마감
16:10  ingest        시세·시총·거래대금·업종·투자자별 수급
16:30  engine        신고가·근접·집계·탐지기·랭킹 → state/YYYYMMDD/*.json
16:35  excel         rankings.json → docs/board/rankings-YYYYMMDD.xlsx
16:40  news          뉴스 수집 → 클러스터링(Batch) → 테마 매칭
17:00  writer        섹터별 병렬 서술 → 검증 → draft.md
17:10  render        대시보드 HTML
17:15  telegram      초안 + 랭킹 요약 발송 (검수용)
17:15~17:50  사용자 검수
18:00  최종 발송 + claims.json 저장
```

`--classify` 는 이 흐름에 없다. 최초 1회와 신규 상장 때만 따로 돌린다.

## 4. 대시보드 탭 구성

| 탭 | 내용 | 원본 |
|---|---|---|
| 신고가 | 달성(테마별 묶음) + 근접 | `newhigh.json` |
| 섹터 랭킹 | 48섹터 순위 + 1~5등, 금일/7거래일 토글 | `rankings.json` |
| 종목 랭킹 | 수익률 순 / 거래량 순 두 표 + 교집합 강조 | `rankings.json` |
| 히트맵 | 크기·색상·그룹 컨트롤 | `sectors.json` |
| 섹터 뉴스 | (뉴스 소스 확보 후) | `news.json` |
| 일간 코멘트 | 검증 통과한 초안 | `draft.md` |

맨 위 **빠진 데이터 배너**는 모든 탭에 공통이다. 무엇이 없는 채로 보고 있는지
모르면 안 된다 (CLAUDE.md 2장 6번).
