# 글로벌 투자 구루 브리핑 계약

매일 아침(화~토 KST) 텔레그램 한 묶음. 글로벌 투자자·테크 리더 36명이 직전 미국장
뉴스 사이클(최근 24시간)에 **직접 한 발언**을 확인하고, 시장 배경·종합 시사점·리스크를
붙인다. 2026-09-29 사용자 요청으로 X 다이제스트(블루스카이 반도체 키워드, `XDIGEST.md`)를
이것으로 **교체**했다. 근거는 `DECISIONS.md` D-NEXT-G.

코드 `board/guru/` · 설정 `board/config/guru.yaml` · 시험 `board/tests/test_guru.py` ·
실행 `xdigest.yml`(이름·dispatch 타입은 외부 스케줄러가 부르는 그대로).

```bash
python3 -m board.run --guru                 # 조사 → 종합 → brief.txt (ANTHROPIC_API_KEY 필요)
python3 -m board.run --send guru --once     # 발송 (이미 보낸 기준일이면 생략)
```

## 1. 양식 — 사용자가 준 예시(2026-09-29) 그대로

```
[※ 확인 못 한 것: …]                                   ← 빠진 것이 있을 때만 (CLAUDE.md 2장 6번)
글로벌 투자 구루 브리핑 | 2026.09.29 (화)

검증 기준: 2026.09.28(월) 미국장 뉴스 사이클 (KST 09.29 06:40 기준 최근 24시간)
당일 발언 확인(PASS): 4명 / 36명 (이름, …)

시장 배경 (9/28 미국장): …

[오늘의 투자 시사점 종합]
매크로 방향성 / 섹터별 힌트 1) 2) … / 주목할 포지션 변화 / 컨트래리언 시그널
[헤지펀드 매니저] · [가치투자/행동주의] · [테크/성장주 전문가] · [기업가/테크 리더] · [트랜스포머 원저자 8인]
이름 (소속)
<발언 요약>            또는   금일 발언 없음 (참고: <최근 발언>)
→ <시사점>
[리스크 & 경고 신호]
1. 제목
본문

수집완료 · 출처(매체 목록) · 다음 브리핑 · 면책 한 줄
```

| 코드가 정하는 것 | 모델이 쓰는 것 |
|---|---|
| 날짜·요일, 기준 시각(실제 조사 시각), PASS 인원·이름, 그룹·인물 순서, 출처 매체 목록, 다음 브리핑 날짜, 결손 줄 | 발언 요약·시사점·참고 문장, 시장 배경 문단, 종합 칸, 리스크 |

- 사용자 예시 머리는 '37명' 이었지만 목록은 36명이다. 머리 숫자는 설정 명단으로 센다.
- 경어체(~했습니다)다 — 사용자 양식을 따른다. X 다이제스트의 '존댓말 쓰지 않는다' 규약은 여기 적용하지 않는다.
- 평문(parse_mode 없음). 4,096자를 넘으면 구획 경계, 그래도 넘으면 빈 줄 경계에서 나눈다.

## 2. 조사 — Claude 웹 검색

그룹 5개 + 시장 배경 1개 = 호출 6번(병렬 3). 모델·단가·검색 상한은 설정에 있다.
`pause_turn`(서버 도구 루프 10회 상한)은 이어 부른다.

**코드가 거르는 것 (research.py)**

1. **출처 URL 은 그 호출의 도구 결과에 실제로 온 것만** — `web_search_tool_result`, dynamic
   filtering 이 결과를 거를 때 오는 코드 실행 결과 블록, 텍스트의 `citations`. 모델이 쓴
   본문·검색어 속 URL 은 세지 않는다. 하나도
   맞지 않는 PASS 는 '금일 발언 없음' 으로 내리고 결손에 센다. 지어낸 URL 을 막는 기계 검사다.
2. **날짜.** PASS 출처는 조사 창(미국 날짜 기준 하루 여유) 안, '참고' 는 `note_days`(30) 안.
3. **명단 밖 이름은 버린다.**
4. **조사 못 한 사람은 '없음' 이 아니라 '확인 못 함'.** 호출 실패·누락을 발언 없음으로 적지 않는다.

**검색 도구 폴백.** 한 그룹의 출처가 **전부** 도구 결과와 어긋나면 결과를 읽는 쪽(도구 버전)의
문제로 보고 `search_tool_fallback`(web_search_20250305)으로 그 그룹만 한 번 다시 조사한다.
비용이 그 그룹만큼 더 들고, 결손 줄에 '재조사함' 이 남는다.

**못 하는 것 — 정직하게.** 검색 결과 본문은 암호화돼 와서 **수치를 기사와 글자 대 글자로
대조할 수 없다.** 출처 URL·날짜까지가 기계 검사의 끝이다. 대신 종합 단계가 새 수치를
만들지 못하게 막는다(3장).

## 3. 종합 — 검색 없음, 새 숫자 금지 (synth.py)

검증을 통과한 발언·참고·시장 배경만 넣는다. 출력의 숫자 토큰이 입력에 없으면 한 번
되묻고, 그래도 남으면 그 칸(리스크·섹터는 그 항목)을 뺀다(CLAUDE.md 2장 3·4번).

## 4. 일정·중복·비용

- 도는 요일: KST 화~토(`run_weekdays`). 일·월 아침은 조사하지 않는다. 미국 휴장일은 거르지 않는다.
- `xdigest-collect` dispatch 는 워크플로가 더 받지 않는다(types 에서 뺐다) — 외부 스케줄러에
  남아 있어도 아무것도 돌지 않고 Actions 분도 안 든다.
- 발송 시각: 양식 06:40. **외부 스케줄러(cron-job.org)의 `xdigest-daily` 를 21:40 UTC 로 옮겨야**
  06:40 에 맞는다(지금은 07:45 KST). 크론 10:23 KST 는 뒤받침이다.
- 중복: `docs/api/guru-sent.json` 표식. 이미 보낸 날 자동 실행은 조사(=비용)조차 하지 않는다.
  부분 발송이면 다시 조사하지 않고 못 보낸 통부터 보낸다(통 목록 지문 — xdigest 규약 재사용).
- 비용: 호출마다 토큰·검색 횟수로 **추정**해 `board/state/guru/cost.json` 에 월별로 쌓는다.
  월 예산(`budget_usd_month`, 30달러)에 닿으면 그날은 API 를 부르지 않고 한 줄 알림만 보낸다.
  검색 단가(1,000회당 10달러)는 공식 가격표로 확인해야 하는 추정값이다.

## 6. 아직 안 된 것

- **실호출을 한 번도 안 했다.** 개발 환경에는 API 키가 없고, Actions 무료 분이 10/1 까지
  소진돼 러너도 못 돈다. 시험은 가짜 클라이언트로 형식·검증 규칙만 본다. 첫 실행 뒤
  `research.json` 의 결손·비용을 보고 검색 상한(`searches_per_person`)을 조정한다.
  도구 버전 문제는 폴백이 스스로 처리한다(2장).
- 블루스카이 다이제스트 코드(`board/xdigest/`)는 지우지 않았다. 워크플로가 부르지 않을 뿐이다.
