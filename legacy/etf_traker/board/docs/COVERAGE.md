# 레퍼런스 코멘트 커버리지

`docs/reference-comment.md` 의 한 줄 한 줄이 무엇을 필요로 하고, 지금 되는지.
writer 를 고칠 때마다 이 표를 갱신한다.

> [KBJ P1] 레퍼런스 코멘트는 사용자가 손으로 쓴 원고라(개인 데이터, ADR 0001 U3) KBJ 에 옮기지 않았다.
> 원래 첫 열은 그 원고 문장을 그대로 인용했는데, 인용을 지우고 문장의 **유형**만 적었다.
> 둘째·셋째 열(필요한 것·상태)은 원본 그대로다. 기록은 `../MIGRATION.md`.

범례

| | 뜻 |
|---|---|
| **계산됨** | board 엔진이 이미 만든다. 사실 팩에 들어간다 |
| **코드 필요** | 소스는 있고 구현만 남았다 |
| **키 대기** | 자격증명이나 소스 결정이 필요하다 |
| **사람 입력** | 자동화 대상이 아니다. `knowledge/*.yaml` 에 사람이 적는다 |

## 1. 장 흐름

| 레퍼런스 문장의 유형 | 필요한 것 | 상태 |
|---|---|---|
| 지수 시가→장중 저점→고점→종가(등락률) 한 줄 | 지수 시·고·저·종 | **계산됨** — `market.json` `indices` |
| 연속 상승·하락 일수 | 연속일 계산 | **계산됨** — `streak` |
| 시장 투자자별 순매수(기타법인·기관·개인) | 시장 투자자별 수급 | **코드 필요** — KIS 앱키 확보. `ingest/kis.py` 붙였고 실호출 미검증 |
| 외국인 순매도 규모의 전일 대비 변화 | 전일 수급 비교 | **코드 필요** — 같은 소스. `_전일` 필드로 사실 팩에 나감 |
| 수급 주체에 대한 추정(예: 자사주 매입 물량) | 사람의 추론 | **사람 입력** — 근거 없이 LLM 이 쓰면 규칙 위반 |
| 코스닥 지수·등락률 | 지수 | **계산됨** |
| 다음 날 해외 실적 이벤트 대기 | 이벤트 캘린더 | **사람 입력** — `knowledge/events.yaml` |
| 업종 등락 상위 셋 | 업종 등락 | **계산됨** — 단, 업종 지수가 아니라 시총가중 계산값 (D-004) |
| 자금 분산·순환매 해석 | 업종 순위 + 신고가 분포 | **계산됨** — LLM 이 서술 |

## 2. 테마 섹션 (원전·재건·해운항공·유통소비재)

| 레퍼런스 문장의 유형 | 필요한 것 | 상태 |
|---|---|---|
| 테마 대표 종목 등락률 나열 | 등락률 | **계산됨** |
| 종목 2일 누적 등락률 | 2일 누적 | **계산됨** — `ret_2d` |
| 밸류체인 단계 나열(설계→PM→주기기 …) | 밸류체인 단계 매핑 | **계산됨** — `themes.yaml` |
| 전일 대비 새로 반응한 단계 | 탐지기 1 밸류체인 확산 | **계산됨** — `stages_new_today` (전일 `sectors.json` 과 차집합) |
| 종목 거래량 배수 | 거래량 배수 | **계산됨** |
| 장중 재료 반납(종가 등락률) | 탐지기 3 재료 반납 | **계산됨** — `%p` 로 렌더 |
| 다중 창 동시 신고가 | 다중 창 신고가 | **계산됨** — `newhigh_all` |
| 전일 코멘트 관점 유지 여부 | 탐지기 7 전일 주장 대조 | **코드 필요** — `claims.json` 저장은 붙였고 익일 대조 판정이 남음 |
| **테마 트리거 뉴스(지분 인수설)** | 뉴스 | **키 대기** — 네이버 검색 API 시크릿 |
| **테마 트리거 뉴스(해외 정세 보도)** | 뉴스 | **키 대기** — 같음 |
| **트리거 뉴스의 매체·단독 여부 유의** | 뉴스 + 매체 판별 | **키 대기** — 매체명은 API 가 준다. 단독 여부 판별은 규칙이 더 필요 |
| 개별 재료(실증 완료 소식 — 뉴스 또는 공시) | 뉴스 또는 공시 | **키 대기** — DART 공시로 절반은 가능 (`ingest/dart.py`) |
| 종목별 기관 순매수 금액과 순위 | 종목별 수급 + 순위 | **코드 필요** — KIS `top_flows` |
| 종목별 외국인·기관 동반 순매수 | 종목별 수급 | **코드 필요** — KIS `stock_flows` |
| 종목 한 줄 설명(무엇을 하는 회사) | 종목 한 줄 설명 | **사람 입력** — `knowledge/notes.yaml` |
| 기업 구조 설명(계약·자산 구조) | 기업 구조 지식 | **사람 입력** — `notes.yaml` `structure` |
| 월간 실적(총매출·증가율) | 실적 공시 | **키 대기** — DART 공시 또는 뉴스 |
| 증권사 리서치 집계 수치 | 증권사 리서치 | **사람 입력** — 자동 소스 없음 |
| 같은 뉴스에 섹터가 양분(항공↑ 해운↓) | 탐지기 2 반대 반응 | **키 대기** — 뉴스 클러스터가 있어야 "같은 뉴스" 를 말할 수 있다 |
| 환율 수준과 며칠째인지 | 환율 + 시계열 | **계산됨** (당일) / **코드 필요** (며칠째인지) |

## 3. 이벤트 리뷰·프리뷰

| 레퍼런스 문장의 유형 | 필요한 것 | 상태 |
|---|---|---|
| 전일 프리뷰 질문에 대한 답 | 프리뷰 ↔ 리뷰 연결 | **사람 입력 + 계산됨** — `events.yaml` 의 `question` 을 익일 리뷰가 받는다 |
| 이벤트 발표 내용(목표치·자사주 소각) | 발표 내용 | **사람 입력** — `events.yaml` `facts` |
| 이벤트 발언 직접 인용 | 직접 인용 | **사람 입력** — `events.yaml` `quotes` |
| 반응 종목 등락률 나열 | 반응 종목 등락률 | **계산됨** — `events.yaml` `tickers` 에 적으면 자동으로 붙는다 |
| 이벤트 반응 해석 | 해석 | **LLM** — 위 사실들이 다 있으면 쓸 수 있다 |
| 전일 대장주의 등락 둔화 | 전일 대비 등락 둔화 | **계산됨** — `ret_2d` 와 당일 등락률 |

## 결론

**지금 자격증명으로 열린 것**

- 투자자별 수급 — 한국투자증권 앱키 확보. `ingest/kis.py` 구현, 실호출 검증 남음
- KRX 업종분류 원본 + 전 종목 시세 — KRX 오픈API 키 확보. `ingest/krx.py` 구현
- 공시 — DART 키 확보. `ingest/dart.py` 구현

**아직 막힌 것**

1. **네이버 검색 API 시크릿** — 클라이언트 ID 만 받았고 시크릿이 없다. 뉴스가 없으면
   "왜 올랐는지" 를 못 쓴다. 레퍼런스에서 가장 값어치 있는 문장들이 전부 여기 걸려 있다.
2. **Anthropic API 키** — 서술 자체를 못 한다.
3. **증권사 리서치 집계** — 자동 소스가 없다. 사람이 적거나 빼야 한다.

**자동화하면 안 되는 것**

이벤트 선정, 종목 구조 설명, 추정. 이건 `knowledge/*.yaml` 에 사람이 적는다.
레퍼런스 코멘트의 값어치 중 상당 부분이 여기서 나오고, 이걸 LLM 에 맡기면
CLAUDE.md 2장 1번(추정을 단정하지 않는다)을 어기게 된다.

**현실적인 목표**

뉴스와 수급이 붙으면 레퍼런스의 약 75%가 자동으로 나온다. 나머지 25%는
`events.yaml` 과 `notes.yaml` 을 채우는 만큼 나온다. CLAUDE.md 1장이 말한
"완전 무인화가 목표가 아니다. 사용자의 작성 시간을 줄이는 것" 과 맞는 그림이다.
