# 일일 노트 계약 (`--send note`)

장 마감 뒤 사람이 쓰는 국장 노트를 텔레그램으로 내보내는 경로의 계약이다.
`report/note.py` 가 읽고 만들며, 입력은 사람이 쓰는 `board/notes/<날짜>.yaml` 하나다.

**랭킹 리포트와 다른 물건이다.** `rankings_message` 는 보드가 계산한 것을 추려
3초에 읽히게 만드는 쪽이고, 이쪽은 **사람의 판단을 나르는** 쪽이다. 그래서 추리는
규칙이 정반대다 — 아래 D4.

---

## 0. 원문의 뼈대

2026-09-21 노트(10쪽)를 뜯어 보니 전부 같은 네 부분의 반복이었다.

```
제목(테마·구분)  →  근거 뉴스  →  종목 + 등락률  →  내 판단
```

이 계약은 그 네 부분을 그대로 옮긴다. 새 구조를 발명하지 않는다 — 이미 쓰고 있는
형식이 읽히는 형식이다.

---

## 1. 입력 — `board/notes/<YYYY-MM-DD>.yaml`

```yaml
# [KBJ P1] 아래 값은 합성 예시다 — 원래 여기 있던 실제 노트 발췌(사용자 판단)는 개인 데이터라
# 지웠다. 모양은 같다. 전체 합성 노트는 tests/fixtures/note_2026-09-21.yaml (synthetic_fixtures.py).
date: 2026-09-21                    # 필수. 보드 state 를 찾는 열쇠
verdict: 합성 판단 — 금리 이벤트 소화 뒤 인프라 업종 위주의 상승   # 필수. 첫 줄에 나간다

index:                              # 선택. 지수·섹터 한 줄씩
  - 코스피 가상지수 +2.31% — 전기전자 주도(합성)
  - 코스닥 — 소부장·전력 인프라 강세(합성)

macro:                              # 선택
  - what: 가상 중앙은행 정책금리 25bp 인상(합성)   # 필수
    note: 반대 2표, 추가 경로 언급 없음            # 선택. 사실 한 줄
    view:                                        # 선택. 내 판단 (여러 줄 가능)
      - "합성 판단: 긴축 의지는 남겼지만 연속 인상 예고는 아님"

themes:                             # 선택
  - name: 전선                      # 필수
    driver:                         # 선택. 왜 올랐나 (사실)
      - 가상 데이터센터 운영사, 비상발전·송배전 설비 대량 발주(합성)
    names: [선도전기, 가상전선01, 가상전선02, 가상전선03, KBI메탈]   # 등락률을 쓰지 않는다
    view:                           # 선택. 내 판단
      - "합성 판단: 영향이 서버를 넘어 발전·송배전 인프라까지 번지는 흐름"

picks:                              # 선택. 세 묶음은 제목만 다르고 모양이 같다
  w52:                              # 52주 신고가 / watch 개별 / surge 급등 포착
    - name: 가상신고01               # 필수
      why: 합성 사유 — 장비사 증설 사이클 수혜   # 선택. 사실
      view: "합성 판단: 공시 종목보다 이런 종목을 더 볼 필요"   # 선택. 내 판단
  watch: [{name: 가상관심01, why: "합성 사유 — 검사장비로 확장"}]
  surge: [{name: 소프트캠프, why: "합성 사유 — 가상 행사에서 신제품 공개", view: "합성 판단: 행사 기간 뒤 고점 가능성"}]

charts: [docs/d/2026-09-21/flows.png]   # 선택. 본문에 붙이지 않는다 (D7)
```

`names` 와 `picks[*].name` 에 **등락률을 적지 않는다.** 적어도 무시한다 — D2.

같은 종목이 여러 구획에 나오는 것은 허용한다. 원문에서 소프트캠프는 보안 테마와
급등 포착에 함께 있었다 — 테마의 일원으로 보는 것과 그날 급등한 것으로 보는 것은
다른 관점이고, 한쪽을 지우면 그 관점이 사라진다. 중복을 없애지 않는다.

---

## 2. 보드가 채우는 값

| 값 | 출처 |
|---|---|
| 등락률 | `state/<날짜>/universe.json` 의 `chg_pct` |
| 시총·거래대금 | 〃 |
| 신고가 라벨(역사적·52주·60일) | `state/<날짜>/newhigh.json` 의 `hits` |
| 종목명 → 종목코드 | 유니버스. 실패 시 유사 후보(`near`) |

`chg_pct` 가 `null` 이면 **0 으로 채우지 않고 수치를 생략한다** (2장 1번).
그 종목은 이름과 사유만 나가고, 머리 결손 줄에 몇 건인지 적는다 (2장 6번).

---

## 3. 렌더 — 3통

실측(2026-09-21 노트 전문) 452 + 826 + 513 = **1,791자**. 한 통에도 들어가지만
나눈다. 한도 때문이 아니라 폰에서 각각 따로 읽히게 하려는 것이다 — D5.

| | 내용 |
|---|---|
| ① | 결손 · 제목 · `verdict` · `index` · `macro` |
| ② | `themes` |
| ③ | `picks` (52주 → 개별 → 급등) |
| ④ | `charts` (있을 때만, `sendMediaGroup`) |

서식은 `report/telegram.py` 와 같다. 레거시 `Markdown`, `_safe`·`_inline`·`_split`·
`_link` 를 그대로 쓴다. 새 헬퍼를 만들지 않는다.

```
*9/21(월) 국장 신고가*
합성 판단 — 금리 이벤트 소화 뒤 인프라 업종 위주의 상승

*지수*
코스피 가상지수 +2.31% — 전기전자 주도(합성)

*매크로*
• 가상 중앙은행 정책금리 25bp 인상(합성) — 반대 2표, 추가 경로 언급 없음
  » 합성 판단: 긴축 의지는 남겼지만 연속 인상 예고는 아님
```

```
*전선*
가상 데이터센터 운영사, 비상발전·송배전 설비 대량 발주(합성)
선도전기 +30% · 가상전선01 +24% · 가상전선02 +13% · 가상전선03 +12%
» 합성 판단: 영향이 서버를 넘어 발전·송배전 인프라까지 번지는 흐름
```

(위 두 블록은 합성 예시다 — 등락률도 지어낸 값이다. KBJ P1 이식, `../MIGRATION.md`)

기호는 셋뿐이다. `*굵게*` 제목 · `•` 사실 · `»` 판단. `»` 는 `draft_message` 가
이미 쓰는 것이라 새로 고르지 않았다. 종목은 줄바꿈 대신 `·` 로 묶는다 — 10종목이면
줄 수가 열 줄이 되고, 그러면 판단이 화면 밖으로 밀린다.

문체는 7장 규칙을 따른다. `~함` 종결, 종목에는 등락률을 동반, 형용사로 강조하지
않는다(수치가 강조를 대신한다).

---

## 4. 발송 전에 멈추는 경우

조용히 넘어가지 않는다. 아래는 **보내지 않고** 사유를 낸다.

- `date` 나 `verdict` 가 없다
- `date` 의 보드 state 가 없다 — 수치를 채울 근거가 통째로 없다
- 이름 중 유니버스에서 못 찾은 것이 있다 → 유사 후보와 함께 이름을 적는다

마지막 것이 특히 중요하다. 오타나 사명 변경을 그냥 통과시키면 그 종목이 노트에서
조용히 빠지고, 빠진 줄 모른 채 읽게 된다. 후보를 적어 주는 규약은
`engine/themes.py`·`web/render.py` 에 이미 있고 그것을 재사용한다.

## 5. 확정한 것과 이유

**D1. PDF 를 자동으로 파싱하지 않는다.** 10쪽 중 5쪽이 이미지라 텍스트 추출로는
통째로 빠지고, 정작 값어치 있는 "셀온 고점 가능성", "테마 플레이로도 위험" 같은
판단은 추출 대상이 아니라 사람이 쓰는 것이다.

**D2. 수치를 사람이 쓰지 않는다.** 손으로 옮기면 출처가 사라지고(2장 2번) 오타가
난다. 보드가 이미 아는 값을 두 번 적을 이유가 없다.

**D3. 이름을 못 찾으면 보내지 않는다.** 2장 6번.

**D4. 내용을 추려내지 않는다. 넘치면 나눈다.** `draft_message` 의 선례다 — 사람이
쓴 판단을 기계가 골라내면 검수할 것도 나를 것도 사라진다. 랭킹 리포트가 추리는
것과 정반대이고, 그래야 하는 이유도 정반대다.

**D5. 3통 고정.** 한도가 아니라 가독성이 기준이다. 분량이 늘어 한 통이 4,096자를
넘으면 그때 `_split` 이 줄 경계에서 더 나눈다.

**D6. 차트는 본문에 붙이지 않는다.** `sendPhoto` 캡션 한도가 1,024자라 본문을 붙이면
잘린다. 따로 `sendMediaGroup` 으로 보낸다.

**D7. 손으로 보낸다 (`board.yml` 모드 `send-note`).** 보드 크론(16:07 KST)에 얹지
않는다. 판단을 쓰는 데 시간이 걸리는데 자동 발송을 걸면 빈 노트가 나간다.

**D8. 노트 파일은 커밋한다.** `board/notes/` 는 생성물이 아니라 원고다. 남겨야
나중에 판단을 되짚을 수 있다.
([KBJ P1] KBJ 는 공개 레포라 `board/notes/` 를 옮기지 않았다 — 사용자 노트는 개인 데이터다
(ADR 0001 U3). 시험은 합성 노트 `tests/fixtures/note_2026-09-21.yaml` 을 읽는다.)
