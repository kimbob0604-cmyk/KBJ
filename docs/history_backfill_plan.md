# 과거 7개년 데이터 구축 계획 (계획만 — 아직 실행하지 않음)

작성 2026-10-18. 대상: 로컬 실행(`scripts/local/kbj.sh`)에서 지금 약 3주(시세)·2021년부터(재무)인 이력을 **7개년(2019-10 ~ 현재)** 으로 늘린다.
숫자는 코드·설정에서 읽은 값과 계산이며, 실측 전은 [확인 필요]로 표시한다.

## 0. 층별 현황과 7년 목표

| 층 | 지금 | 7년 목표 | 방법 | 막는 것 |
|---|---|---|---|---|
| 시장 일봉·업종·ETF(KRX) | 2026-09-28~10-15 | 2019-10 ~ | `market.backfill` | KRX 하루 호출 5,000건 |
| 재무(DART 주요계정) | 2021~ | 2019~ | `config/fin.yaml backfill.from_year` 2019 로 + `fill-dart` | DART 하루 8,000건 |
| 투자자별 수급·프로그램 | 오늘부터 쌓임 | 7년 | **KIS 로는 불가 [확인 필요]** | 원천 한계(§3) |
| 밸류에이션·신고가 | 짧은 이력 | 7년 | 위 둘이 끝난 뒤 재계산 | 선행 의존 |
| 컨센서스·공시 | 꺼짐/오늘부터 | 해당 없음 | 과거 이력은 원천이 없다 | — |

## 1. 시장 일봉 7년 (가장 쉽다)

- 호출량: 거래일 약 1,720일 × 하루 10개 호출(종목기본정보 2·일별매매 3·지수 3·ETF·ETN) ≈ **17,200건**.
  `krx.backfill_cap` 5,000/일 → **약 4일**(하루 약 500거래일). 속도 2/s 라 하루치 5,000건은 약 40분.
  (코넥스·ETN 이용신청이 없으면 그 호출은 0행으로 건너뛴다 — 호출은 그날 처음 401 한 번.)
- 명령(최근 → 과거 순서, 이어받기 가능):
  `bash scripts/local/kbj.sh backfill 2500` — 일수 인자 상한(1100)을 2600 으로 올리는 작은 수정이 먼저 필요.
  (또는 컨테이너에서 `scheduler backfill market.backfill --from 2019-10-01 --to 2026-09-27 --max-days 500` 을 4일 반복.)
- **KRX 가 2019 년 일별 자료를 주는지 [확인 필요]** — 설정의 원천 바닥은 2010-01-04 로 적혀 있으나 실측 전이다.
  첫날 `--from 2019-10-01 --to 2019-10-04` 4일로 먼저 시험한다.
- **수정주가 위험(가장 중요):** KRX 일별 시세는 액면분할·무상증자 등으로 과거 가격이 불연속이다. 신고가·이동평균·밸류에이션 밴드는
  수정주가가 필요하다. 코드에 ETF 분할 이벤트(`split_event`)는 있으나 **일반 종목의 수정계수 적용은 확인되지 않았다 [확인 필요]**.
  7년 이력을 채우기 전에 수정계수 소스(KRX 권리 이벤트 vs DART 공시 vs 가격 불연속 감지)를 정해야 한다 → **먼저 설계·시험**.
- 신고가 라벨: `board.yaml hist_source_floor` 를 실제 시작일(예 2019-10-01)로 맞추면 "N종목은 이 날 이후 최고가 기준"으로 표시된다.
- 저장 용량 [추정]: 일봉 약 2,800종목 × 1,720일 ≈ 480만 행 + ETF 150만 행 → DB 1~3GB. Docker Desktop 디스크 여유 20GB 이상 확인.

## 2. 재무 7년

- `config/fin.yaml backfill.from_year: 2021 → 2019`(FY2019~FY2025 = 7개 회계연도 + 2026 분기). 추가분은 2개 연도 ≈ 8분기라 지금 한 번 돈 양의 약 1/3.
- 지금 `tier: main`(주요계정). 상세 재무제표(`full`)는 관심종목에만 — 7년 상세가 필요하면 관심종목을 먼저 정한다(호출량 큼).
- 실행: `kbj.sh fill-dart`(이미 받은 것은 건너뛰고 이어 받음). 하루 8,000건 한도라 한 번에 안 끝나면 다음 날 반복.
- 끝나면 밸류에이션 재계산(`valuation rebuild --as-of <전 거래일>`) — `fill-dart` 4단계가 이미 한다.
- 주의: 회사코드 변경·합병·상장폐지 종목의 과거 재무는 현재 회사코드 표(`corp_code`)에 없으면 빠진다(생존 편향) [확인 필요].

## 3. 수급(투자자별)·프로그램 — 원천 한계

- KIS 일별 투자자 API 는 종목당 **최근 약 한 달**만 준다 [확인 필요 — 실측 필요, probe_results §7 #22]. 7년 소급은 KBJ 가 쓰는 원천으로는 불가로 본다.
- 선택지: (A) 오늘부터 쌓는다(가장 단순, 1년 뒤 1년치). (B) KRX 정보데이터시스템 '투자자별 거래실적' 수동 다운로드 CSV 를 가져오는 일회성
  가져오기 도구를 새로 만든다(개인 용도 약관 확인 필요). (C) 필요한 건 시장 전체 합계뿐이라면 KRX 일별 합계만 가져온다.
- 프로그램매매 일별은 `program.backfill`(60거래일)로 제한. 꺼진 상태 — 실측 #40 뒤.
- 결정 필요: 수급 7년이 꼭 필요한가? (A)로 충분한지.

## 4. 순서와 일정(제안)

1. **시험(반나절):** 2019-10 첫 4일 백필이 되는지, 수정주가 문제가 보이는지(분할 종목 한두 개 확인).
2. **수정주가 설계(결정 후 구현):** 소스 선택 → 가격 정규화 층 추가 → 신고가·MA·밸류에이션이 그 층을 읽게 → 시험.
3. **시세 4일 백필:** 하루 5,000건씩, 매일 같은 명령(맥 깨어 있게 `awake on`).
4. **재무 from_year 2019:** 설정 변경 → `fill-dart` 1~2일.
5. **재계산:** 역사적 신고가(`board.rebuild_alltime` 자동), 밸류에이션 `rebuild`.
6. **검증:** 임의 종목 5개의 7년 차트·재무를 원천 사이트와 대조. 분할 종목·상장폐지 종목 포함.
7. **백업:** `kbj.sh backup --now` 로 덤프(복구 리허설 1회).
