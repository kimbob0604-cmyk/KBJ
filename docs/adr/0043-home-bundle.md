# ADR 0043 — 첫 화면 묶음 경로 `/api/home`: 카드별 봉투·격리·개인 데이터 없음·여러 영역 버전 키 (2026-11-10)

상태: **채택**(첫 화면 1/2 — 서버. 화면은 다음 단계가 이 경로로 만든다). 근거: 사용자 요청 "KBJ 첫 화면(페이지 1)을 Beom's
Dashboard 처럼 요약 카드 중심으로" 와 조사 메모(카드별 KBJ 데이터 대응표 — 묶음 경로 권장 ①~⑦).
구현: `kbj/services/api/readers/home.py`·`models/home.py`·`routes/home.py`, 새 값 `kbj/engines/market/movers.py`
(`/api/market/movers`), 정의 `docs/metrics.md` §6.8(급등·급락)·§14(서프·쇼크 갈래)·§32(카드 고르기).

## 1. 맥락

- Beom's Dashboard 첫 화면은 묶음 파일 하나(home.json)로 카드 십여 장을 그린다. KBJ 의 기존 경로로 같은 화면을 그리면 요청이
  15~20개, 공개 사이트 파일로 0.8MB 가 넘는다(공시 일정 400KB·잠정실적 151KB·1분 수급 36KB×3). 카드에 필요한 것은 건수와
  몇 줄뿐이다.
- 공개 사이트(ADR 0042)는 인자 없는 GET 을 전부 내보낸다 — 묶음에 개인 데이터가 들면 그대로 공개된다.
- 응답 캐시(`deps.cached_json`)는 키에 영역 하나의 데이터 버전을 쓴다 — 여러 영역을 읽는 묶음에 영역 하나만 주면 다른 영역
  작업이 쓴 새 값이 TTL 동안 옛 본문에 묶인다(docs/realtime_audit.md R4 와 같은 문제).

## 2. 결정

1. **얇은 묶음**: `GET /api/home` 은 기존 읽기 함수를 불러 카드마다 필요한 몇 줄만 고른다(계산 두 벌 금지). 새로 필요한 값
   (급등·급락)은 먼저 자기 경로(`/api/market/movers`)와 metrics 정의로 만들고 묶음이 그 함수를 부른다. 큰 시계열·기간 토글
   (1년 차트·1분 수급 선·업종 지도 전체)은 묶음에 넣지 않는다 — 화면이 기존 경로를 따로 부른다.
2. **카드마다 봉투와 상태**: 카드 14장(`indices`·`futures`·`filings`·`breadth`·`spike`·`movers`·`foreign_inst`·`newhigh`·
   `gex`·`diag`·`program`·`etf`·`themes`·`export`)이 각자 source·as_of·quality·notes 와 상태(`ok`·`no_data` + 서버 안내 문구·
   `error` + 사유 코드)·링크 페이지(`page`)·같은 값을 주는 경로(`keys`)를 싣는다. 한 카드의 실패는 그 카드만 `error` 로 —
   다른 카드는 그대로 만든다(절대 규칙 4). 오류 내용은 로그에만(가린 문구 — 절대 규칙 5), 응답에는 코드만.
3. **개인 데이터 없음**: 관심종목·규칙 신호·관심종목 가산이 든 공시 중요도(importance·login_score)·잠정실적 alerted 는 고르지
   않는다. 공시는 키워드 점수(kw_score — 공개 규칙)로 고른다. 시험이 관심종목을 비워도 묶음 값이 같은지 본다.
4. **여러 영역 버전 키**: `cached_json(domain=…)` 이 영역 여럿을 받아 버전을 이어 붙인다(`HOME_DOMAINS` — market·flows·
   flows_minute·board·gex·diag·filings·etf·themes·program). 영역 작업 목록을 묶음용으로 한 벌 더 만들지 않는다(두 벌 금지).
   시험이 카드 `keys` 경로들의 영역이 `HOME_DOMAINS` 에 모두 드는지 본다. 오류 카드가 있는 본문은 캐시에 두지 않는다.
5. **기본값**: 급등·급락 하한 3,000억·보통주만, 공시 상위 8·서프/쇼크 4, 급증 10, 외국인·기관 5씩, 신고가 8, ETF 5일·종목 3,
   테마 1일·5개 — Beom's 첫 화면과 각 페이지 기본 보기를 따른 값이다 [확인 필요 — 사용자].

## 3. 결과·위험

- 장중에는 GEX(사이클 ≈30초)·1분 수급 영역 버전이 자주 바뀌어 묶음이 거의 매분 다시 만들어진다(카드 14장의 읽기 — 원장은
  LedgerCache 가 공유). 카드는 일꾼 6개가 나눠 만든다(`HOME_WORKERS` — 공유 읽기는 키마다 한 번). 맥 실측(2026-11-10, 원장
  캐시 뒤) 약 3초 — docs/probe_results.md. 하위 경로의 캐시 본문을 다시 쓰지는 않는다(느리면 다음 단계에서 GEX 브리핑의 전략
  계산을 떼는 것부터 검토).
- 시장별 상승·하락, 60·120일선 비율, 선물 전일 대비 등락률, 장중 시장 프로그램 누적은 아직 원천 경로가 없다 — 카드 notes 에
  '없다'고 적는다(지어내지 않는다). 서프·쇼크는 컨센서스 대비가 아니라 전년동기 대비 방향이다(분기 컨센서스 없음).
- 공개 사이트에는 full 묶음(인자 없는 GET)으로 자동으로 실린다. 장중 10분 묶음(live)에 넣을지는 화면 단계에서 정한다
  (`config/site.yaml` — 이 단계에서는 바꾸지 않았다).
