## 0. 공통 원칙

- **일별 원장 하나에서 모두 계산한다.** 종목·ETF마다 `(날짜, 거래대금, 투자자별 순매수 …)` 일별 행을 저장하고, 1일·5일·20일 값, 순위, 연속일, 상단 띠 숫자는 전부 이 원장에서 계산한다. 화면마다 따로 받은 숫자를 섞지 않는다. 그래야 페이지끼리 숫자가 어긋나지 않는다.
- **기간 = 영업일.** 거래 캘린더(`kbj.core.calendar`) 기준이다. 휴장일은 행이 없다. "5일"은 오늘을 포함한 최근 5영업일이다.
- **단위.** 금액은 원 단위 정수로 저장하고, 화면에서 억·조로 바꾼다. 반올림은 화면에서만 한다.
- **모든 값에 `source`·`as_of`·`quality`를 붙인다.** 장중 값은 `estimated`(잠정), 마감 확정 뒤 `ok`, 다음 영업일 KRX 대조 뒤에도 차이가 있으면 `invalid`로 두고 원인을 남긴다.

## 1. 거래대금

| 항목 | 정의 |
|---|---|
| 거래대금(일) | 그날 체결 금액 합(원). 정규장과 시간외를 나눠 저장한다. 화면 기본값은 **정규장 + 시간외 합계**다 [확인 필요] |
| 거래소 범위 | **KRX와 넥스트레이드(NXT)를 나눠 저장**하고 합계를 따로 둔다. KRX 자료만 쓰면 NXT 체결분이 빠져 거래대금과 순매수가 작게 나온다 [실측 필요: KIS·KRX 응답이 통합인지 KRX만인지] |
| 기간 거래대금 | 기간 영업일 거래대금의 합 |
| 일평균 거래대금 | 기간 합 ÷ 그 종목이 실제로 거래된 영업일 수. 거래정지일은 분모에서 뺀다 |
| 회전율(%) | 일평균 거래대금 ÷ 기간 마지막 날 시가총액 × 100 |
| 거래대금 급증 배수 | 오늘 거래대금 ÷ 직전 19영업일 평균. 직전 거래일이 10일 미만이면(신규상장 등) 계산하지 않는다(`quality=invalid`, 표시 없음) |
| 시장 거래대금 | 코스피 + 코스닥 종목 합. ETF·ETN·리츠는 따로 집계한다(섞으면 레버리지 ETF 거래대금이 시장 거래대금을 부풀린다) |

**출처 후보:** KRX OpenAPI 일별 매매정보 `stk_bydd_trd`·`ksq_bydd_trd`(`ACC_TRDVAL`, D+1 08:00), 장중·당일은 KIS 거래량 순위 `FHPST01710000` [실측 필요: 거래대금 정렬 옵션, 상위 몇 개까지].

## 2. 투자자별 순매수

| 항목 | 정의 |
|---|---|
| 순매수(원) | 매수 금액 − 매도 금액. 수량이 아니라 **금액**을 기본으로 쓴다 |
| 투자자 구분 | 외국인(외국인 + 기타외국인), 기관(아래 7구분 합), 기타법인, 개인 |
| 기관 7구분 | 금융투자, 투신, 사모, 보험, 은행, 연기금, 기타금융 |
| 검산 ① | 한 종목·하루의 외국인 + 기관 + 기타법인 + 개인 = 0 (장내 순매수 합). 0이 아니면 그 행은 `invalid` |
| 검산 ② | 기관 7구분 합 = 기관 합계 |
| 연속 순매수(일) | 오늘부터 거꾸로 세어 순매수 > 0 인 연속 영업일 수. 0원인 날, 순매도인 날, 거래정지일에서 끊긴다 |
| 외인·기관 동반 | 기간 외국인 순매수 > 0 이고 기관 순매수 > 0 |

**검산 불가(메인 결정 R2, 2026-10-07):** 검산 ①은 4구분이 **모두** 있을 때만 한다. KIS 종목별 투자자 TR(FHKST01010900)이 기타법인을 주지 않으면(3구분 — [실측 필요]) 실데이터에서는 ①을 할 수 없다. 그때는 잔차를 0 으로 바꾸지 않고 **검산 불가**(`None`)로 두고, 사유("기타법인 미제공")를 응답 `notes`·`docs/probe_results.md` 에 기록한다. 기관 7구분이 없으면 ②도 같다. P3 완료 기준 "검산 0 차이"는 **가능한 검산은 0 차이, 불가한 검산은 사유 기록**으로 읽는다. 합성 원장에서는 ①②③ 전부 강제한다(§5).

**장중 값과 확정 값:** 장중 외국인·기관 수치는 증권사 **추정치**(KIS `FHPTJ04400000` 외국인·기관 매매종목 가집계 [실측 필요])라 `quality=estimated`다. 마감 뒤 확정치(KIS `FHKST01010900` 종목별 투자자, KRX)로 덮어쓰고, 덮어쓴 차이를 기록한다. 장중 순위 화면에는 "잠정"을 표시한다.

**출처:** KIS(로그인). KRX 정보데이터시스템 스크래핑은 쓰지 않는다(conflict_map Q7). 기관 7구분이 KIS에서 되는지는 [실측 필요]이다. 안 되면 기관 합계만 쓰고 7구분 패널은 숨긴다(빈 값을 0으로 그리지 않는다).

## 3. 스크리닝

| 기준 | 정렬 키 | 거르는 조건 |
|---|---|---|
| 거래대금 상위 | 기간 거래대금 | — |
| 외국인 순매수 | 기간 외국인 순매수 | — |
| 기관 순매수 | 기간 기관 순매수 | — |
| 외인·기관 동반 | 기간 외국인 + 기관 순매수 | 둘 다 > 0 |
| 연속 순매수 | max(외국인 연속일, 기관 연속일), 같으면 순매수 합 | 3일 이상 |
| 거래대금 급증 | 급증 배수(기간과 무관, 오늘 기준) | 1.5배 이상 |

공통 필터: 시장(전체·코스피·코스닥), 기간(1·5·20일), 일평균 거래대금 하한(기본 300억 [확인 필요]). **관리종목·거래정지·정리매매 종목은 기본으로 뺀다.** 우선주는 보통주와 따로 나온다. 결과 표에는 신고가 여부(board 엔진)와 급증 배수를 함께 표시한다.

엔진에 정한 세부(묶음 E2 — `kbj/engines/flows/{screen,streak}.py`, 전부 [확인 필요]):

| 항목 | 정한 값 |
|---|---|
| 대상 종목 | 보통주(`common`)·우선주(`pref`)만. 스팩·리츠·ETF·ETN 은 뺀다. '전체' 시장 = 코스피 + 코스닥(코넥스 제외) |
| 연속 순매수 동점 | 연속일이 같으면 **기간 외국인 + 기관 순매수 합**이 큰 쪽이 앞 |
| 연속일 상한 | 최대 60영업일까지 거슬러 센다(`STREAK_LOOKBACK`) |

## 4. ETF 수급

| 항목 | 정의 |
|---|---|
| 순유입(설정 − 환매, 원) | Σ (좌수ₜ − 좌수ₜ₋₁) × NAVₜ. 가격이 올라 늘어난 순자산은 넣지 않는다. 좌수 = **유효 좌수**(아래) |
| 가격효과(원) | Σ 좌수ₜ₋₁ × (NAVₜ − NAVₜ₋₁) |
| 유효 좌수 | 보고 순자산(`INVSTASST_NETASST_TOTAMT`) ÷ NAV(= 함의 좌수, 반올림)를 그날 좌수로 쓴다. KRX 상장좌수는 설정·환매를 늦게 싣는다 — 국내형 다음 거래일, 해외 자산 2~3거래일(결제 T+2~T+3), 미결제 설정 단위가 상장좌수에만 먼저 잡히기도 한다(실측 2026-10-20: 하루만 맞추자 남은 검산 실패 515일의 83% 가 해외주식). 함의 좌수가 그날 또는 `LAG_MAX`(3) 거래일 안의 상장좌수와 같으면 그 좌수(확인). 뒤 거래일이 모자란 최근 날은 함의 좌수를 `estimated`(확인 전)로, 뒤 거래일이 다 있는데 어느 것과도 안 맞으면 상장좌수 그대로(보고값 의심 — 검산 ③ 이 잡는다). 허용 = (0.005원 × 좌수 + 공표 단위) ÷ NAV + 1좌. 보고 순자산이 없으면 상장좌수 |
| 검산 ③ | 순자산 변화 = 순유입 + 가격효과 (차이 0, 반올림 오차만 허용) |
| 투자자별 ETF 순매수 | 장내 매매의 투자자별 순매수. 상대가 대부분 LP라 순유입과 다를 수 있어 **따로** 보여 준다(합치지 않는다) |
| 괴리율(%) | (종가 ÷ NAV − 1) × 100. 절댓값 0.5% 이상이면 경고 [확인 필요: 해외·채권형은 기준을 따로 둘지] |
| 유형별 순유입 | 국내 대표지수 · 국내 테마 · 해외주식 · 레버리지·인버스 · 채권·현금 · 원자재. 분류는 `etf_tracker_v9/themes.classify`(ADR 0001 Q8) |

**오류가 나기 쉬운 곳 (구현 전에 테스트로 막는다):**
1. **분할·병합.** 분할일에는 좌수가 몇 배로 늘고 NAV가 같은 비율로 준다. 그대로 계산하면 가짜 대규모 순유입이 생긴다. 분할·병합 이벤트 표를 두고, 그날은 이전 좌수와 NAV를 분할 비율로 맞춘 뒤 계산한다. 테스트: 1:10 분할일 순유입 = 0.
2. **분배금 지급일.** NAV가 분배금만큼 떨어진다. 이것은 가격효과이지 유출이 아니다. 좌수 기준 공식이라 자동으로 맞지만, 테스트로 고정한다.
3. **신규 상장·상장폐지.** 상장 첫날 좌수 전체를 유입으로 세지 않는다(전날 행이 없으면 순유입 계산 제외, 첫날 순자산은 '신규'로 따로 표시). 상장폐지 전날까지 계산한다.
4. **NAV 기준 시점.** 장 마감 NAV(확정)만 쓴다. 장중 iNAV는 괴리율 경고에만 쓴다.
5. **레버리지·인버스.** 거래대금이 커서 상위 순위를 덮는다. 유형 필터를 기본 제공하고, 시장 거래대금에는 넣지 않는다(§1).

**출처 후보:** KRX OpenAPI ETF 일별 매매정보 `etf_bydd_trd`(NAV, 상장좌수 `LIST_SHRS`, 순자산 `INVSTASST_NETASST_TOTAMT`, 거래대금) [실측 필요: 필드 이름·공표 시각], KIS ETF 현재가 `FHPST02400000`(장중 NAV·괴리율), 구성종목은 운용사 어댑터 또는 KIS `FHKST121600C0` [실측 필요].

**원장 원천 우선순위(P3 — docs/p3_design.md D-P3-7, `kbj.core.rows.ledger_rank`):** 한 (종목, 날짜, 투자자/지표) 의 값은 **krx(ok) > kis(ok, 마감 확정) > kis(estimated) > kis.prelim(장중 가집계)** 하나만 쓴다. invalid 는 다른 행이 없을 때만 남아 집계에서 빠지고 수가 세어진다. 같은 원천·품질이면 거래소 KRX > 구분 없음 > TOTAL > NXT. 마감 확정 수집은 같은 키의 장중 잠정 행을 덮어쓰고 차이를 `prv_flows.investor_revision`(잠정 값·확정 값·차이·시각)에 같은 트랜잭션으로 남긴다. 확정 뒤 늦게 온 잠정은 쓰지 않는다. 투자자별 순매수는 KRX 대조 원천이 없어 KIS 마감값이 최종(ok)이다. 종가·거래대금·시총은 다음 영업일 KRX 확정치와 대조해(§6.6) 어긋나면 KIS 행을 invalid 로 바꾸고 사유를 남긴다.

## 7. 신고가 정의 (P3 — board 엔진, 신고가 3축 — ADR 0017)

> **정본은 엔진 문서화 문자열**이다: `kbj/engines/board/newhigh.py` 머리말. 이 절은 요약이고 둘이 다르면 엔진 쪽이 맞다(정의를 바꾸면 이 절·ADR·골든 재캡처를 함께). 숫자는 `config/board.yaml` 한 곳.
>
> **2026-10-08 사용자 요청으로 축을 바꿨다(ADR 0017)** — "특정일 기준이 아니라 당일 기준으로 52주 전·120일 전과 비교해 52주·120일·역사적 3축". 예전 정의(ET CLAUDE.md 4장: 60일 = 직전 60영업일, 52주 = 직전 252영업일 — 그 종목 봉 수)는 대체됐다. ETF-Traker·stock-dashboard 원본도 같은 정의로 바꿨다.

| 항목 | 정의 |
|---|---|
| 120일 신고가(`d120`) | 판정일 직전 **120 시장 거래일**(KRX 거래일 달력 — 판정일 전 120번째 거래일 ~ 전 거래일)의 최고가를 당일 **초과**. 창의 경계는 시장 거래일로 정하고 그 안의 그 종목 봉만 본다 — 거래정지로 창이 늘어나지 않는다. `newhigh.lookback_trading_days.d120: 120` |

| 역사적 신고가(`hist`) | **상장 이후 전체**(판정일 전까지) 최고가를 당일 초과. 스칼라(`prv_board.alltime`)로 들고 매일 당일 값과만 비교. 특정일 '이후' 가 아니다(아래 깊이) |

| 신규·이어감 | 직전 영업일에 같은(또는 상위) 라벨이 없었으면 신규, 있었으면 이어감. 직전 보드가 없거나 **다른 신고가 정의로 계산됐으면** '모름'(status_unknown — 정의 전환일. 저장된 전일 산출의 정의 지문으로 매번 판단하므로 재실행해도 같다) |

| 근접 클러스터(탐지기 9) | 한 테마에서 근접 종목 ≥ `detect.proximity_cluster_min`(3) |
| 근접 후 후퇴(탐지기 10, 옛 '돌파 실패') | 어제 근접(갭 ≤ 5%)이던 종목의 오늘 같은 기준 갭이 어제보다 커짐 — 강도 = 갭 증가 %p. 지수 급락일엔 시장 베타로 많이 잡힌다(화면 설명) |
| 수정주가 가드 | 하루 종가 변화 > ±31%(`integrity.split_guard_ratio`)면 분할·병합 미반영 의심(suspect) — 역사적 신고가 판정에서 빼고, 그 지점 이전 구간이 120일·52주 창에 걸리면 그 축을 계산하지 않는다. 공시 대조(`prv_board.split_check`)가 '분할 아님(none)'이면 가드를 푼다. 조회 실패(unknown)는 풀지 않는다 |
| 복수 기준 탐지(탐지기 6) | 120일·52주·역사적 중 `detect.multi_label_min`(2) 종 이상 = 52주 이상. 라벨이 겹쳐 신고가 표와 같은 것을 세므로 **화면에서 뺀다**(API 에는 남는다) |
| 계산 안 되는 값 | `None` — 채워 넣지 않는다 |

**역사적 신고가의 깊이(메인 결정 R8, D-P3-11, ADR 0017):** 네이버 출처의 옛 역사적 최고가(ET `board.db` `alltime`)는 **옮기지 않는다**(U4). 스칼라의 `history_from` 은 **시장 일봉을 빠짐없이 받아 둔 첫날**이다(`kbj.services.engine.board.market_history_from` — 종목의 첫 봉이 아니다. 받지 못한 거래일·몇 종목뿐인 날에서 끊는다). 판정 규칙(`newhigh.hist_depth`):
- 상장일(`universe.listed_on`) ≥ `history_from` → 상장 이후 전체 → 판정.
- 아니면 `history_from` ≤ **원천 바닥**(`newhigh.hist_source_floor` — KRX 일별 시세가 주는 가장 이른 날, **[실측 필요 — 체크리스트 #21]**, 지금 `2010-01-04`) → 더 받을 수 없으므로 판정하고, 화면·API 품질 메모에 "N종목은 <바닥일> 이후 최고가 기준" 을 **한 번** 적는다(`hist_scope.n_since_floor`).
- 둘 다 아니면 보류 + 사유("이력이 상장일 전에서 끊김"·상장일을 모르면 "상장일을 몰라 …") — 짧은 구간으로 조용히 대신하지 않는다. 종목 행 `hist_note`, 수는 `hist_scope.n_before_listing`·`n_listing_unknown`, 화면에는 품질 메모 한 줄.

화면·API 는 역사적을 "YYYY-MM-DD 이후" 로 내세우지 않는다 — 기준 줄은 "역사적 = 상장 이후, 52주 = 달력 52주, 120일 = 120거래일". 이력을 상장일까지 채우는 길: `python -m kbj.services.scheduler backfill market.backfill --to-listing`(이미 받은 첫날 전날부터 max(가장 이른 상장일, 원천 바닥)까지, 최근부터 과거로, 하루 예산 `krx.backfill_cap` 에서 멈추면 다음 날 같은 명령이 이어 받는다) → 범위를 다 받으면 `rebuild_alltime`.

**확정:** 장 마감 보드(`board.daily` 16:00 — 마감 수집이 끝나면, KIS 마감 스냅. ADR 0018)는 `estimated`, 다음 영업일 08:40 `board.confirm` 이 KRX 확정 일봉으로 다시 계산해 `ok` 로 덮는다(바뀐 라벨 목록을 남긴다).

### 8.2 분할·병합 감지와 보정 (§4 오류 1번)

| 항목 | 규칙 |
|---|---|
| 감지 | Sₜ ÷ Sₜ₋₁ ≈ k **이고** NAVₜ₋₁ ÷ NAVₜ ≈ k (k ∈ 2·3·4·5·10·20·50·100 — 분할, 또는 1/k — 병합). 상대오차 `etf.split_tol` 2%. 좌수만 늘고 NAV 가 그대로면 큰 설정이지 분할이 아니다(두 조건 동시) |
| 비율 | ratio = 새 좌수 ÷ 옛 좌수(1:10 분할 = 10, 5:1 병합 = 0.2) |
| 보정 | 그날은 Sₜ₋₁ × ratio, NAVₜ₋₁ ÷ ratio 로 맞춘 뒤 §4 공식으로 계산 → `status=split_adjusted` |
| 기록 | `prv_etf.split_event(origin=detected, quality=estimated)`. 수기 표(`origin=manual`)가 있으면 그것이 우선이고 감지가 덮지 않는다 |
| 기대값(시험) | 1:10 분할일 순유입 = 0, 5:1 병합일 순유입 = 0, 큰 설정(좌수 10배·NAV 그대로)은 분할로 보지 않는다 |

  `total_debt`·`short_inv`·`net_debt`·D&A·EBITDA·EPS 는 **None**(0 으로 채우지 않는다). 그 층의 EV/EBITDA 는 `not_detail_tier`.
- **전체 재무제표 층**에 차입 계정 줄이 하나도 없으면 그 계정은 0 으로 본다 [확인 필요 #35 — 태그 분포 실측 뒤]. 별도(OFS)
  재무제표의 비지배지분은 0(별도에는 비지배지분이 없다).
- **금융업 매출 동의어**('보험수익'·'순영업수익' — ET `NAMES`)는 legacy 매출 이름이 비었을 때만 매출 자리에 쓰고 notes 에 남긴다
  [확인 필요 #35].
- **기준(CFS↔OFS)이 바뀐 분기**의 비율 행은 estimated(위 '연결/별도' 행 — 혼재).
- **YoY 부호 전환**(전년 같은 분기와 부호가 다름)은 비율 None + notes('흑자전환'·'적자전환' 문자) — 위 YoY 행과 같다.
- **PIT 접수일**: 한 분기 값의 접수일 = 그 값을 만든 보고서 접수번호 앞 8자리 중 늦은 것(차분이면 직전 보고서까지). 정정 보고서는
  원시 행을 덮어 그 분기의 접수일이 정정일로 밀린다 — 원 공시일~정정일 사이 그 분기를 포함한 TTM 은 None(엄격 PIT — 보수적).
  원 공시일(`pub_filings.disclosure` 의 첫 접수)을 쓸지는 **[결정 필요 — ADR 0016 §5-4]**.

1. **주당 값의 분모**: DART 주식총수(보통주 발행 − 자기주식, PIT)가 그날 KRX 보통주 상장주식수와 30% 안이면 DART 수, 아니면 KRX
   상장주식수(estimated + notes).
2. **분할 직후 보고 EPS**: 보고된 주당 값(분기 기본주당이익 합·KIS 추정 EPS)이 함의하는 주식 수가 위 분모와 30% 넘게 다르면 총액 ÷
   분모로 다시 세고 근거 문자열을 `TTM_NI_PER_SHARE`·`CONSENSUS_NI_PER_SHARE` 로 적는다(합성 #17 액면분할 5:1).
   주요계정 층(기본주당이익 없음)의 TTM EPS 도 `TTM_NI_PER_SHARE`.
3. **비지배지분 줄이 없는 연결 재무**: 0 으로 보고 EV 를 세며 estimated + notes [확인 필요 #35].
4. **회사 시총**: 스냅 `mktcap`(KRX 원장), 없으면 종가 × 상장주식수. 우선주가 빠지면 빼고 estimated. **보통주가 빠지면 회사 시총을
   만들지 않는다**(그날 행은 `missing_input`).
5. **밴드·시나리오는 그날 행이 있는 전 종목**(주요계정 층 포함 — EV/EBITDA 칸만 `not_detail_tier`). 등록부 `fin.valuation_band` 노트와 같다.
6. 시세 과거가 늘어나는 KRX 일별 백필(`market.backfill`) 뒤에는 `python -m kbj.services.engine.valuation rebuild --as-of <전 거래일>`
   을 한 번 돌린다(재무 지문은 시세 백필을 잡지 못한다 — 재무 백필·정정은 지문이 다시 계산). `docs/PLAN.md` P4 운영 절차.

**적용 불가 사유(`na_reason`) — 한 칸에 사유는 하나(2026-10-13 묶음 S 확정 — 묶음 V `multiples.NA_PRIORITY`·A API·합성 기대 행렬 `tests/fixtures/synthetic/p4_expect.yaml` 이 같은 규칙, 완료 시험이 확인).**
여러 사유가 겹치면 앞의 것: `currency_mismatch`(재무 통화 ≠ KRW) > `no_filings`(정기보고서 없음) > `spac` > `financial_sector`(EV/EBITDA·매출총이익·EBITDA) > `not_detail_tier`(EV/EBITDA — 주요계정 층) > `short_history` > `loss`·`capital_impairment`·`no_revenue` > `missing_input`.
TTM 이 없는 까닭에 따라: 신규상장으로 상장 뒤 정기보고서가 4분기에 못 미침 → `short_history`(현재 배수도 — 밴드와 같은 사유), 반기·연간 보고만 해 분기 단독을 만들 수 없음(리츠·코넥스 — §9 `derived`) → `missing_input`. 사유가 있는 칸의 값은 None 이다(0 으로 채우지 않는다).

우선주의 시나리오는 **회사(보통주) 기준**이다 — EPS·BPS·밴드는 회사 것, 가격·업사이드는 보통주 종가(화면에 '보통주 기준').

⚠ **[결정 필요 — 메인·사용자, ADR 0016 §5-5] 주당 값과 회사 배수의 기준이 어긋난다.** 배수(밴드)는 회사 시총(보통 + 우선, 자기주식
포함 — §11 '자기주식 차감 안 함')으로 세는데, 시나리오의 BPS·`*_NI_PER_SHARE` 분모는 보통주 발행 − 자기주식이고 TTM EPS 는 DART
기본주당이익이다. 그래서 현재 배수를 그대로 곱해도 업사이드가 0 이 아니다(합성 #1 — 우선주 6천만·자기주식 560만/보통주 4억: PBR 폴백·
`*_NI_PER_SHARE` 경로 +14.3%, `TTM_EPS` 경로 −0.9%. 우선주 없이 자기주식 20% 인 회사는 모든 경로 약 +25%). 밴드가(§11 밴드 차트)는
주당 기준값 = 종가 ÷ 그날 배수라 어긋나지 않는다. 고치는 길: **① [권고] 시나리오 주당 값 = 총액 × 보통주 종가 ÷ 회사 시총**(밴드가와 같은
기준 — §11 규칙 ②의 분할 보정도 필요 없어진다) 또는 ② 회사 시총에서 자기주식을 빼고 우선주는 따로. 정해지기 전까지 화면의 업사이드는
이 차이를 포함한다(구현은 위 표 그대로).

| 항목 | 정의 |
|---|---|
| 추정 raw | DART 지분 공시(PIT — 접수일 ≤ 계산 날짜): 1 − (자기주식 + 5% 대량보유 보고자별 마지막 보유) ÷ 보통주 발행주식. 보고자 이름이 재무적 투자자 패턴(`fif_estimate.financial_holder_patterns`)이면 빼지 않는다. 발행주식 없음·비유동 ≥ 발행 → None. quality estimated [확인 필요: 지수별 전략적 보유 정의] |

| 범위 | 시총 상위 `fif_estimate.top_n`(400) + 구성종목만 추정(저장소 호출 상한) — 밖은 None → 컷오프 추정에서 빠진다(노트에 수) |

신규) × C(세그먼트를 모르면 `segment_default` — migrate, 노트에 수)·T_f = add_ff_mult(0.5) × C, 구성종목 T_m =
keep_mcap_mult(⅔) × C·T_f = keep_ff_mult(⅓) × C. 적용 FIF < min_fif_add(15%)면 T_f = low_fif_ff_mult_add(0.9)·
_keep(0.6) × C. `light_rebalance.enabled` 면 비구성종목 1.8·0.9(GIMI 2026-08판 §3.1.5·§3.1.6·App.VIII).

| 열 | 식 |
|---|---|
| 시가총액 M | 기준일 스냅 시총(원 — 원장 우선순위 KRX > KIS) |
| 유동시총 F | M × 적용 FIF(반올림·완충·FOL 뒤) |
| 시총 컷오프 괴리율 | g_m = M ÷ T_m − 1 |
| 유동시총 컷오프 괴리율 | g_f = F ÷ T_f − 1 |
| 조건 충족(O/X) | M ≥ T_m 그리고 F ≥ T_f(⇔ g_m ≥ 0 그리고 g_f ≥ 0) |
| 필요 주가 상승률 | r = max(T_m ÷ M, T_f ÷ F) − 1 을 **1bp 올림**(주식 수·FIF 고정 — 유동시총도 (1 + r) 배). 기준(basis) = 큰 쪽(시총·유동). 음수 = 그만큼 떨어져도 조건 유지. 역산: (1 + r) 배면 넘고 r − 1bp 면 못 넘는다(속성 시험). 다른 종목·컷오프는 고정 |
| 예상 패시브 매매 | §24.5 |
| 거래대금 배수 | \|예상 패시브 매매\| ÷ 일평균 거래대금(일봉 `adv_days` 일 평균, 원) |

판정(g = min(g_m, g_f)): \|g\| < borderline(10%) → 경계, 아니면 구성종목 g ≥ 0 유지·g < 0 편출, 비구성종목 g ≥ 0 편입·
g < 0 후보 아님(저장 안 함). 비구성종목 FIF < min_fif_add(15%) → 0.9× 문턱으로 예외 편입(low_fif 배수가 없는 지수 —
FTSE — 는 편입하지 않고 경계), foreign room < 15% → 편입하지 않고 경계(주가로 풀 수 없음). FIF 를
모르면 시총 조건만 보고 편입·유지 대신 경계(estimated). 대상 밖(거래정지·정리매매·우선주) 구성종목은 편출 후보, 시세가
없는 구성종목은 경계(단정하지 않음). 성질: 컷오프 고정에서 시총이 오르면 판정이 나빠지지 않는다(속성 시험).

### 24.4 컷오프 추정(MSCI 형)

MSCI 는 컷오프를 공표하지 않는다 → 시장 커버리지 방식: 대상 종목을 전체 시총 내림차순으로 놓고 유동시총을
누적해 전체 유동시총의 coverage(85%)에 처음 닿는 종목의 **전체 시총**. 구간 = coverage_high(90% — 낮은 값)~
coverage_low(80% — 높은 값). 컷오프 종류 model(추정, estimated). 사용자가 증권사 추정치를 넣으면(`set-cutoff` —
`review_calendar.user_cutoff_won`) 같은 입력으로 kind user 를 **나란히** 계산·저장한다. 성질(속성 시험): 동차(모두
k 배 → k 배), coverage ↑ → 컷오프 비증가, 한 종목 시총 ↑ → 그 종목의 '컷오프 이상' 여부 비악화.

### 24.6~24.7 KRX 형(KOSPI200·KOSDAQ150) — 2차 자료 근사 [확인 필요: KRX 방법론 원문·2026-11-02 개정판]

대상 = 설정 시장·보통주·관리/거래정지/정리매매 아님. 심사 시총 M = 심사기간(6개월 — 12월 변경은 5~10월) 일평균 시총
(작업: 최근 `mcap_avg_days`(125) 거래일 평균 종가 × 기준일 상장주식 수), 창의 절반 미만이면 기준일 시총으로 대체(노트 —
추정). 산업군(DART 업종코드 앞 2자리 → `sectors.map` — KRX 산업군과 다르다. 2026-11-02 부터 KRX KRICS 9개 산업군,
2026-10-26 공개 뒤 매핑 [확인 필요·TODO])마다 M 내림차순으로 산업군 안 순위 p·산업군 구성종목 수 n:
신규 = p ≤ floor(n × add_rank_ratio) 이고 산업군 누적 시총 비중 안(자기보다 큰 종목 비중 < `sector_cum_mcap` — 문턱에
처음 닿는 종목까지), 유지 = p ≤ floor(n × keep_rank_ratio). 값: KOSPI200 0.9/1.1·85%, KOSDAQ150 0.8/1.2·60%(삼성증권
2026-03-27). 문턱 = 경계 위치 종목의 M, 괴리율 = M ÷ 문턱 − 1, 필요 상승률 = 문턱 ÷ M − 1(1bp 올림, 다른 종목 고정),
유동 괴리율은 없음(—). 대표 컷오프(화면) = 산업군 신규 문턱 가운데 최저값. 유동성: 산업군 안 거래대금 순위 백분위 ≤
liquidity_pct, 모르면 보류(경계). 상장 min_listing_days(6개월) 미만 신규는 제외(전체 순위 ≤ fast_entry_rank 면 특례).
정원 맞추기: 편입 뒤 수 > size → 순위 낮은 편입 후보를 경계로, < size → 다음 순위 비구성종목(막힘 없는 것)을 채움.
예비종목 제도는 2026-11-02 개정으로 폐지(엔진에 없다). '제외 가능'(유지 한도 밖) 종목을 정원에 맞춰 작은 순으로만
빼는 KRX 절차는 아직 옮기지 않았다(지금은 유지 한도 밖 = 편출 후보).

### G1 입력 전처리 (PLAN §5.1)

#### G1.1 옵션 가격 선택
- 정의: IV 역산에 쓸 옵션 한 종목의 가격
- 공식: 매수·매도 호가가 모두 있고 `(ask − bid) ≤ 3 × tick(bid)` 이면 `mid = (bid + ask) / 2`, 아니면 `last`. 둘 다 없으면 제외
  - `tick(p)` 는 §G2.1 옵션 호가단위(p ≥ 10pt 이면 0.05, 미만 0.01). 호가가 10pt 경계를 걸칠 때 **bid 기준 틱**으로 센다 **[확인 필요]**
- 입력: bid, ask, last (전광판 행), 당일 누적 거래량 `volume`(KIS `acml_vol`, 모르면 없음). 단건 현재가 보강 행(`source=fill`)은 호가가 없어 `last` 만
- 단위: pt
- 예외: bid 또는 ask 가 0·빈 값이면 호가 없음으로 본다. last 가 0·빈 값이면 last 없음
  - ask < bid(역전 호가 — 단일가 접수 중 스냅샷 등)도 호가 없음으로 보고 last **[확인 필요]** — 식을 글자 그대로 따르면 음수 스프레드라 mid 가 된다
  - **전 세션 가격**: 고른 가격이 `last` 인데 `volume = 0` 이면 그 last 는 전 세션 값으로 본다(`PriceChoice.prev_session`) **[확인 필요]**. 근거: `docs/validation_greeks.md` §G5.4 — 2026-09-28 위클리 ATM±5 22행 중 10~19행이 당일 거래 없이 전 세션 last 로 역산돼 합성 F 가 +28~31pt(WKM 261001) 어긋났다. `volume` 을 모르면(없음) 표시하지 않는다(지금 동작). mid 는 살아 있는 호가라 거래량과 무관하다. 야간 세션의 `acml_vol`·last 가 어느 세션 기준인지는 실측 전이다
  - 전 세션 가격의 쓰임 **[확인 필요]**: §G1.3 F 에는 쓰지 않는다(§G1.3). IV·그릭스·GEX 에는 그대로 쓰되 그 종목 품질(`OptionEval.quality`)을 `estimated` 이상으로 둔다 — 사유 `prev_session_last`(`OptionEval.quality_reasons`). 종목 품질은 §G2.1 만기 품질·§G3.7 ATM IV 품질에 합성된다
- 품질: 선택된 가격이 있으면 ok, 없으면 해당 종목 제외(품질 아님). 전 세션 가격이면 위 규칙
- 테스트: 스프레드 3틱 경계(=3틱 mid, 3틱+ last), 10pt 경계 틱, 호가 한쪽만 있음, 둘 다 없음, 역전 호가, 거래량 0 인 last(전 세션)·mid·거래량 모름

#### G1.2 프리미엄 하한
- 정의: 수치 불안정 종목 제외
- 공식: 선택 가격 < 0.02pt 이면 IV·그릭스 계산 제외. 그 종목 OI 는 GEX 에서 **기본 제외**, `excluded_oi_ratio = 제외된 OI 합 / 전체 OI 합` (범위별)
  - 판정은 `IvResult.below_min_premium`(§G1.5 결과의 명시 플래그)으로 한다. KIS IV 가 있으면 §G1.5 폴백으로 `sigma` 가 `estimated` 로 채워지지만(IV 표시용), 자체 그릭스는 계산하지 않고 GEX 는 IV 품질·`sigma` 유무와 무관하게 이 플래그로 제외한다 **[확인 필요]** — §G1.2 "계산 제외"와 §G1.5 "1.2 로 제외 → KIS 폴백"이 겹치는 부분의 해석. KIS 그릭스는 어떤 경우에도 GEX 폴백으로 쓰지 않는다(2026-09-28 사용자 결정, PLAN §5.1) — 이 행들은 GEX 에서 빠진 채로 제외 OI 비율에만 든다
- 입력: 1.1 의 가격, OI
- 단위: 비율(0~1)
  - 분자 "제외된 OI" 는 §G1.2 제외뿐 아니라 GEX 에 못 들어간 **모든** 종목의 OI — 가격 없음(§G1.1), IV `invalid`(§G1.5), 그 만기 F 없음(§G1.3) **[확인 필요]**. 비율이 GEX 가 덮지 못한 OI 몫을 뜻하게 한다. KIS 폴백 `sigma`(`estimated`)로 그릭스를 계산한 종목은 포함이라 분자에 없다
- 예외: 전체 OI 합 0 이면 `excluded_oi_ratio = 0`
- 품질: 비율 자체는 ok. 순GEX 품질에 연동(§G2.2)
- 테스트: 0.019/0.02 경계, 비율 계산, OI 0, KIS IV 가 있어도 `below_min_premium` 이 서고 GEX 에서 빠짐

#### G1.3 합성선물 F
- 정의: 만기별 Black-76 기초자산
- 공식: 기준가 S_ref(선물 근월물 현재가)에 가장 가까운 행사가를 ATM 으로, ATM±2(최대 5개) 행사가 중 콜·풋 가격(1.1)이 모두 있는 행사가마다 `C − P + K`, 그 **중앙값**
  - ATM 을 고를 기준가는 선물 근월물 현재가 — 전광판 `atm_cls_name` 은 쓰지 않는다(probe_results #11a)
  - **S_ref 출처는 세션으로 고른다** (2026-09-29 사용자 결정, `kbj.core.gex.forward.select_s_ref`): 주간 = 선물 전광판 `F`(`fut_board` 의 day·`F`·board 행), **야간 = 단건 `CM` 시세(`fut_board` 의 night·`CM`·single 행) — 전광판 `F` 는 야간에 주간 종가로 고정된다(probe_results #19, 분기 B)**. 다른 출처로 대체하지 않는다: 야간에 전광판 `F` 행이 더 최근이어도 쓰지 않고, `CM` 시세가 없으면 S_ref 없음(그 사이클 F 없음). 같은 세션 태그·근월물 코드·값 있음·invalid 아님·now 이전 행 중 가장 최근. 나이 90초 초과면 `stale`(PLAN §6.1 과 같은 기준), 행 품질이 더 나쁘면 그것. 이 S_ref 가 ATM 선정·근월물 + 베이시스 기준가(아래)·확정 베이시스(`confirm_basis`)에 같이 쓰인다
  - 콜·풋 중 하나라도 **전 세션 가격**(§G1.1, 당일 거래량 0 인 last)인 행사가는 쓰지 않는다 **[확인 필요]** — 설정 `prev_session_in_forward`(기본 false, `core.gex.PREV_SESSION_IN_FORWARD`). 창은 넓히지 않는다(ATM±2 그대로) — 남은 행사가 수로 아래 품질·선물 대체 규칙을 그대로 적용(3 개 미만 `estimated`, 2 개 미만 선물 대체, 기준가 없이 0 개면 F 없음). 뺀 행사가는 `ForwardResult.prev_session_skipped`. 근거: `docs/validation_greeks.md` §G5.4(위클리 F +28~31pt), 적용 뒤 결과는 같은 문서 §G5.6(위클리 F 어긋남 사라짐, ATM±2 가 전부 전 세션 가격인 위클리는 F 없음)
- 입력: 만기 한 개의 행사가별 콜·풋 가격(전 세션 표시 포함), S_ref(= 근월물 선물가 — 주간 전광판 `F`·야간 단건 `CM`, 위), (분기 월물이면) 같은 결제월 선물 현재가, 그 만기의 확정 베이시스(아래 선물 교차 확인 — 호출 쪽이 들고 있는 값)
- 단위: pt
- 예외: 쓸 수 있는 행사가가 0 개면 — 선물 기준가가 있으면 선물 대체(아래), 없으면 F 없음 → 그 만기 전 지표 `invalid`. 중앙값이 0 이하여도 F 없음(방어선 — 기준가가 있어도 대체하지 않는다)
- 품질: 쓸 수 있는 행사가가 3 개 미만이면 `estimated` **[확인 필요]**. 만기가 분기 월물(3·6·9·12월 월물)이면 같은 결제월 선물가와 비교해 |F − 선물가| > 0.5pt 면 `estimated`(PLAN §5.1, 0.5 정확히는 ok, 사유 `futures_gap`). 여기에 아래 선물 교차 확인(2pt·선물 대체)이 더해진다
  - 분기 월물 판정: 만기 코드가 만기일의 YYYYMM 과 같고(월물 — 위클리는 YYMMWW, probe_results #12) 월이 선물 결제월(`kbj.core.gex.specs`). 분기 월물인데 같은 결제월 선물가가 없으면 0.5pt 비교는 건너뛰고(품질 유지) **[확인 필요]**, 선물 교차 확인은 근월물 + 베이시스 기준가로 한다

#### G1.5 IV
- 정의: 종목별 내재변동성
- 공식: Black-76 역산 `vollib.black.implied_volatility(price, F, K, r, T, flag)`
- 입력: 1.1 가격, 1.3 F, K, 1.4 T, (폴백) 같은 종목 KIS `hts_ints_vltl`(%)와 그 만기 T_KIS(§G1.7)
- 단위: 연율(소수, 0.25 = 25%)
- 예외: 역산 실패(내재가치 아래, 수렴 실패, 1.2 로 제외) → KIS `hts_ints_vltl`(% 단위 → /100) 폴백 + `estimated` — 폴백 σ 는 아래 **T 환산** 으로 자체 T 에 옮긴다. KIS 값도 없거나 0 이면 `invalid`. 사유 코드 `IvResult.reason`:
  - `invalid_price`: 가격 nan·inf → 폴백 (1.1 이 먼저 걸러야 하는 방어선)
  - `below_min_premium`: 1.2 로 제외(가격 < 0.02pt, 0.02 는 계산) → 폴백
  - `below_intrinsic`: 가격 ≤ 할인 내재가치 `e^(−rT)·max(±(F − K), 0)` → 폴백. 내재가치와 **같은** 가격도 여기 넣는다 **[확인 필요]** — vollib 은 같으면 σ = 0 을 내므로 그대로 두면 아래 이상치(`invalid`)가 된다. 대안: 같으면 `invalid`
  - `above_max`: 가격 ≥ 무차익 상한(σ → ∞ 극한, 콜 `e^(−rT)·F`, 풋 `e^(−rT)·K`) → 폴백 **[확인 필요]** — 대안: §G6.1 가격 이상치로 보고 `invalid`
  - `model_error`: vollib 예외 또는 nan 결과(수렴 실패) → 폴백
  - 폴백 KIS 값이 없음·0·nan 이면 `<사유>/kis_missing`, KIS 값 자체가 음수·inf·> 300% 면(T 환산 뒤에도 > 300%) `<사유>/kis_out_of_range`, KIS 값은 0 < σ ≤ 300% 인데 T 환산 뒤 > 300% 면 `<사유>/kis_out_of_range_rescaled`(§G6.1 — 아래 T 환산) → `invalid`

  - 모든 폴백 σ 에 적용한다 — §G1.2 제외 종목의 표시용 σ, §G3.4 Flip·§G3.7 ATM IV 가 쓰는 sigma 도 옮긴 값이다

#### G2.1 행사가별 GEX
- 정의: 딜러 1% 기초자산 변동당 감마 익스포저(naive 딜러: 콜 롱·풋 숏)
- 공식: `GEX_call(K) = + Γ_c(K) × OI_c(K) × m × F² × 0.01`, `GEX_put(K) = − Γ_p(K) × OI_p(K) × m × F² × 0.01`, `GEX(K) = GEX_call(K) + GEX_put(K)`
- 입력: 1.6 감마, OI(KIS `hts_otst_stpl_qty`), m, 그 만기 F
- 단위: 원 / 기초자산 1%. 표시 억원(÷ 1e8)
- 예외: 1.2 로 제외된 종목(`IvResult.below_min_premium`, IV 품질과 무관)은 0 으로 두고 `excluded_oi_ratio` 에 반영. 가격 없음·IV `invalid` 종목도 같다(§G1.2 분자). 그 외 종목은 IV `sigma`(자체 또는 KIS 폴백)로 §G1.6 그릭스를 계산해 포함
- 품질: 입력 품질 합성 — 그 만기 F 품질과 포함 종목 IV 품질 중 가장 나쁜 것(제외 종목의 IV 품질은 비율로만 반영)
  - 종목 품질 = IV 품질, 전 세션 가격(§G1.1)이면 `estimated` 이상 **[확인 필요]** — 포함 종목 하나라도 전 세션 가격이면 그 만기는 `estimated`(OI 몫과 무관 — §G1.2 비율 같은 OI 가중은 명세에 없다)
  - 행사가별 표는 행과 함께 품질·`excluded_oi_ratio` 를 낸다 — 같은 종목의 §G2.2 합산과 같은 규칙(제외 비율 > 10% estimated, F 없음·OI 전부 제외 invalid). 여러 만기를 합친 표(§G3.1)는 범위 전체 비율로 다시 잰다
- 테스트: `tests/unit/core/gex/test_sign_conventions.py` — 콜 OI 만 있으면 양수, 풋 OI 만 있으면 음수, 같은 감마·OI 면 콜+풋 = 0, 단위 계산 예시 값 고정

#### G2.2 순GEX
- 정의: 범위 안 모든 행사가·만기의 GEX 합. 양수 롱감마, 음수 숏감마
- 공식: `Σ GEX(K)` — 범위: 전체 / 최근접 만기 / 0DTE(당일 만기) 각각
- 단위: 원/1% (표시 억원)
- 예외: 범위에 종목 없으면 null
  - 최근접 = 범위 후보 중 가장 이른 만기일(만기 지난 만기는 상위에서 뺀다, §G1.4). 0DTE = 만기일이 그 거래일인 만기
  - 범위가 비면(만기일이 아닌 날의 0DTE 등) 값 null·품질 ok — 해당 없음이지 품질 문제가 아니다 **[확인 필요]**
  - F 없는 만기가 범위에 있으면 품질 `invalid`(§G1.3 "그 만기 전 지표 invalid"), 값은 F 있는 만기만의 합. F 있는 만기가 하나도 없으면 null
  - 범위에 OI 가 있는데 전부 제외됐으면(전체 OI > 0, 포함 OI = 0 — `excluded_oi_ratio = 1`) 값 null·품질 `invalid` **[확인 필요]** — 합이 0 이 아니라 덮은 OI 가 없어 모른다. F 는 있어도 모든 종목이 §G1.2·§G1.5 로 빠진 경우. 전체 OI 가 0 이면(포지션 없음) 값 0·제외 비율 0 그대로
- 품질: `excluded_oi_ratio > 10%` 면 `estimated`(PLAN, 10% 정확히는 아님), 입력 품질 합성
- 테스트: 범위별 합, 10% 경계, 전부 제외 → null·invalid, OI 전부 0 → 0

#### G2.3 DEX
- 정의: 딜러 델타 익스포저
- 공식: `DEX = Σ OI_c·Δ_c·m·F − Σ OI_p·Δ_p·m·F` (풋 델타 음수라 딜러 풋 숏 델타는 양수)
- 단위: 원(기초 가치 기준). 억원 표시
- 예외·품질: §G2.2 와 같게 — 같은 제외 규칙·범위, `excluded_oi_ratio > 10%` 면 `estimated`, 입력 품질 합성 **[확인 필요]**
- 테스트: 부호(콜만 → 양수, 풋만 → 양수 — 딜러 풋 숏의 델타는 양수)

### G3 핵심 레벨 (PLAN §5.2)

#### G3.1 콜월
- 정의·공식: 콜 GEX(`GEX_call`) 최대 행사가
- 예외: 동률이면 현재가(F)에 가까운 쪽. 콜 OI 전부 0 이면 null
  - 범위(만기)는 호출 쪽이 고른다(§G2.2 all·nearest 등). 행사가별 GEX 는 범위 안 만기들의 합이고 F 없는 만기는 빠진다
  - "현재가(F)" 는 §G3.4 기준 F(F 있는 만기 중 가장 이른 만기의 F). 거리도 같으면 낮은 행사가(`kbj.core.gex.chain` ATM 동률 규칙과 같게) **[확인 필요]**
  - null 은 콜 GEX 가 0 보다 큰 행사가가 없을 때 — 콜 OI 전부 0 과 콜이 전부 GEX 에서 제외된 경우(§G2.1) **[확인 필요]**
- 품질: 범위 순GEX 품질(§G2.2 — F 없는 만기 invalid, 제외 OI 비율 > 10% estimated, 입력 품질 합성) **[확인 필요]**. §G3.2·§G3.3 도 같다
- 테스트: 최대·동률 규칙

#### G3.2 풋월
- 정의·공식: 풋 GEX 절대값(`|GEX_put|`) 최대 행사가
- 예외: 동률 규칙 3.1 과 같음
- 테스트: 최대·동률

#### G3.3 절대감마 행사가
- 공식: `|GEX_call(K)| + |GEX_put(K)|` 최대 행사가. 동률 규칙 3.1

#### G3.4 감마 전환점(Flip)
- 정의: 총 GEX 가 부호를 바꾸는 가상 기초자산 가격
- 공식: 격자 `F′ ∈ [0.95F, 1.05F]`, 0.25pt 간격. 각 F′ 에서 sticky-strike IV(종목별 IV 고정)로 감마를 다시 계산해 총 GEX(F′)(§G2.1 식의 F 자리에 F′) 재계산 → 이웃 격자점 사이 부호가 바뀌는 구간마다 선형보간으로 교차점
  - 만기 여러 개를 합칠 때 만기별 F 가 다르다 → 각 만기 F 를 같은 비율 `F′/F_기준`으로 옮긴다(기준 = 최근접 만기 F) **[확인 필요]**
  - 최근접 만기에 F 가 없으면 기준은 F 있는 만기 중 가장 이른 만기의 F **[확인 필요]** — 그 범위 품질은 §G2.2 로 invalid
  - 격자: `0.95F + 0.25·i` 로 1.05F 를 넘지 않게, 1.05F 가 격자에 없으면(1e-9pt 넘게 떨어짐) 끝점으로 덧붙인다 — 마지막 간격만 0.25pt 보다 짧다 **[확인 필요]**
  - 재계산 대상은 §G2.1 GEX 에 든 종목(제외 종목은 0). 종목 IV 는 그 종목 sigma(자체 역산 또는 KIS 폴백), T 는 그대로
- 단위: pt
- 예외: 교차점 0 개 → `none`(범위 전체 같은 부호), 2 개 이상 → F 에 가장 가까운 것 + `multi_cross = true`. 격자점에서 정확히 0 이고 0 이 아닌 양옆 가장 가까운 값의 부호가 다르면 그 점이 교차점(0 이 여럿 이어지면 그 구간 가운데) **[확인 필요]**
  - 같은 부호 사이의 0(접함)·격자 끝의 0·격자 전부 0 은 부호가 바뀌지 않으니 교차가 아니다(정의·PLAN §5.2 "부호 변화 지점"). 0DTE 막판(T 하한 5분)엔 행사가에서 먼 F′ 의 감마가 언더플로로 정확히 0 이 되어 0 구간이 생기는데, "0 인 격자점은 전부 교차점" 으로 읽으면 그 구간 격자점마다 가짜 교차점이 된다. 그 해석은 인자 `zero_rule="every_zero"` 로 고를 수 있다(기본 `"sign_change"`, `core.levels.FLIP_ZERO_RULE`)
  - F 와의 거리가 같은 교차점이 둘이면 낮은 쪽 **[확인 필요]**
- 품질: 입력 품질 합성 — 범위 순GEX 품질(§G3.1 과 같다)
- 테스트: 한 번 교차(선형 체인 합성 예제), 0 번(전부 콜) → none, 두 번 → 가장 가까운 것·multi_cross, 격자 끝, 정확히 0 인 격자점(양옆 부호·접함·끝·0 구간, `every_zero` 설정)

#### G3.5 전환점 거리
- 공식: `(F − Flip) / F × 100` (%). Flip 없으면 null
  - F 는 §G3.4 기준 F

#### G3.6 0DTE 레벨
- 정의: 당일 만기만으로 3.1·3.2·3.4. 만기일에만 활성(그 외 null)
  - "당일" 은 귀속 거래일(§G2.2 `trade_date`) — 야간은 T+1 귀속이라 금요일 야간엔 월요일 만기 위클리가 0DTE(§G2.2 0DTE 정의 그대로). 기준 F 는 그 만기 F

#### G3.7 ATM IV (PLAN §5.4 — 기대변동폭 입력)
- 공식: F 를 사이에 두는 두 행사가 K1 ≤ F ≤ K2 에서 각각 `(IV_call + IV_put) / 2`, F 로 선형보간. F 가 행사가와 같으면 그 행사가 값
- 예외: 둘 중 한쪽 행사가의 콜·풋 IV 가 모두 없으면 있는 한쪽 값만 쓰고 `estimated` **[확인 필요]**, 둘 다 없으면 `invalid`
  - 한 행사가에 콜·풋 IV 중 하나만 있으면 그 값을 그 행사가 값으로 쓰고 `estimated` **[확인 필요]**
  - F 가 행사가 범위 밖이면 없는 쪽 행사가를 "IV 없음" 으로 보고 위 규칙(있는 쪽만, `estimated`) **[확인 필요]**. F 가 행사가와 같은데 그 행사가 IV 가 없으면 `invalid`
  - IV 는 sigma 가 있는 종목 — 자체 역산(ok)·KIS 폴백(estimated). §G1.2 제외 종목의 표시용 sigma 도 쓴다. 품질은 종목 품질(§G2.1 — 전 세션 가격이면 `estimated`)
- 품질: 만기 F 품질과 쓴 IV 품질 합성, 위 예외면 `estimated` 이상

#### G3.8 기대변동폭 ±1σ
- 공식: `F × IV_ATM × √Δt`
  - Δt(년): 세션 중이면 현재 세션 종료까지, 세션 밖이면 다음 세션 전체의 남은 분을 **달력 기준으로 연환산 — ÷ (365 × 24 × 60)**. 2026-09-28 사용자 결정: IV 가 달력 분 T(§G1.4)로 역산되므로 Δt 도 같은 기준. PLAN 의 "거래시간 기준 연환산"(÷ 252 × 420분, 주간 한 번 = 1/252년)은 옵션 인자(`basis="trading"`)로만 둔다. 두 값의 차이는 `docs/validation_greeks.md` 에 나란히 적는다
  - 세션 경계는 `kbj.core.calendar.session_bounds`(주간 15:45, 야간 익일 06:00). 만기일 종목의 15:20 종료는 반영하지 않는다(기초자산 기준) **[확인 필요]**. 세션 밖이면 지금 뒤에 시작하는 첫 세션(휴장·야간 미개장 건너뜀) 전체 — 주간 420분, 야간 720분
  - F·IV_ATM 은 같은 만기(보통 최근접)
- 품질: IV_ATM 품질 불량(invalid)이면 `invalid`. 아니면 IV_ATM 품질(§G3.7 — F 품질 포함)
- 테스트: 세션 중·세션 밖, 식 값

#### G3.9 기대범위 내 상위 GEX 레벨
- 공식: `[F − 1σ, F + 1σ]` 안 행사가를 `|GEX(K)|` 내림차순 상위 N(기본 5)
- 예외: 범위 안 행사가가 N 개보다 적으면 있는 만큼
  - F·1σ 는 §G3.8 결과, 범위 양 끝 포함. GEX(K) 는 호출 쪽 범위(만기)의 행사가별 합(§G3.1), GEX 0 인 행사가도 후보
  - `|GEX(K)|` 동률이면 F 에 가까운 쪽, 거리도 같으면 낮은 행사가 **[확인 필요]**
- 품질: §G3.8 품질과 범위 순GEX 품질 합성. §G3.8 이 invalid 면 빈 목록·`invalid`

#### G3.10 만기별 감마 소멸액

- 품질: 만기 목록 품질 연동 — 만기 목록(KIS 월물리스트) 품질을 인자로 받아 만기마다 순GEX 품질(§G2.2)에 합성 **[확인 필요]**

  최고/최저·거래량 배수)는 창 안에 `None` 이 하나라도 있으면 `None`. **재귀 지표**(EMA·RSI·MACD·ATR·
  ADX)는 결측 칸을 건너뛴다 — 그 칸 출력은 `None`, 상태는 직전 유효 칸에서 이어진다(결측 칸을 지운
  배열로 계산해 제자리에 펼친 것과 같다). 정지일이 없으면 board 원본(`systems.py`·`signals.py`)과 같은 값.
- 계산은 float64, 왼쪽→오른쪽 누적 순서 고정(board 와 같은 부동소수 순서 — numpy 없음). 비교는
  허용오차(골든 1e-12, 실시간 대 백테스트 근거 값 1e-9).
- anchor = `max(rules.anchor_date, 종목 첫 봉)`(기본 `2020-01-02` **[확인 필요]**). 지표는 언제나 anchor
  부터 한 번에 계산하고 실시간은 마지막 칸·백테스트는 각 칸을 읽는다(D-P8-7 — EMA 계열 시작점 고정).
- 품질 = 입력 중 가장 나쁜 quality(장중 부분 봉·장중 잠정 수급은 `estimated`). 출처 = 입력 데이터셋.

### 30.1 지표 공식

| 지표 | 공식 | 예외·주 | 시험 |
|---|---|---|---|
| SMA(n) | 최근 n 칸 산술 평균 | 창 안 `None` 이 하나라도 있으면 `None` | 손계산·선형성 |
| EMA(n) | 시드 = 첫 n 유효 칸 SMA(칸 n−1), 이후 `e += α(x − e)`, α = 2/(n+1) | board `ema_arr` 와 같음 | board 값 표·상수열 고정점 |
| RSI(n) | 와일더: 첫 n 변화의 평균 이득·손실 → `(g·(n−1)+x)/n`, `100 − 100/(1+g/l)`, l = 0 이면 100 | 워밍업 `None`(SD 의 0.0 채움 폐지) | board `rsi_arr` 값, 0~100 |
| MACD(f,s,sig) | line = EMA(f) − EMA(s), signal = line 의 EMA(sig)(line 의 첫 유효 칸부터 시드), hist = line − signal | f < s | 손계산 |
| 볼린저(n,k) | mid = SMA(n), σ = 모표준편차(n), upper/lower = mid ± kσ, %B = (close − lower)/(upper − lower), width = (upper − lower)/mid | σ = 0 이면 %B `None`, mid = 0 이면 width `None` | board `pstdev`·`bb_width` 값 |
| 밴드폭 백분위(n,k,lookback) | 그날 포함 직전 lookback 칸의 width 중 그날 값의 순위 백분위 — 동점 평균 순위 r, `(r−1)/(lookback−1)×100`(§D0 와 같은 규칙) | lookback 미달·창에 `None` → `None` | 손계산 |
| TR·ATR(n) | TR = max(h−l, \|h−c₋₁\|, \|l−c₋₁\|)(c₋₁ = 직전 유효 종가, 없으면 h−l), ATR 시드 = 칸 1..n 의 TR 평균(칸 n — board `turtle_n`), 이후 `(ATR·(n−1)+TR)/n` | 첫 칸 TR 은 h−l | board `true_range`·`turtle_n` 값 |
| ADX(n) | +DM/−DM → 와일더 평활 → +DI/−DI = 100·DM/ATR, DX = 100·\|+DI−−DI\|/(+DI+−DI), ADX = DX 의 와일더 평균 | +DI/−DI 칸 n 부터, ADX 칸 2n−1 부터, 입력 2n+1 칸 미만이면 전부 `None` | board `adx_arr` 값 |
| 거래량 배수(n) | 오늘 거래량 ÷ 직전 n 칸 평균(오늘 제외) | 평균 0 → `None`. 장중은 누적 거래량(시간 보정 없음) | 손계산 |
| N일 최고·최저(n) | 직전 n 칸 high 최대·low 최소(오늘 제외) | 창에 `None` → `None` | 손계산 |
| 등락률 | (close / 직전 유효 종가 − 1) × 100 | 전일 정지면 직전 유효 종가, 첫 칸 `None` | 손계산 |
| 연속 순매수·N일 합 | §2 정본(`kbj.engines.flows.streak`), 합은 원 단위 — 창 안 값이 하나라도 없으면 `None` | 장중은 아래 §30.2 | 기존 시험 |
| 고점 대비 하락 | 보유 시작 칸 이후 최고 high 대비 (close/peak − 1) × 100 | 포지션 없으면 `None` | 손계산 |
| 신고가(축) | board 엔진 3축(`d120`·`52w`·`ath` — ADR 0017) 산출을 읽는다(다시 계산하지 않는다) | 마감 전용 | board 시험 |

### 30.2 장중 부분 봉·장중 수급 (D-P8-9 + 사용자 결정 2026-10-13)

- 부분 봉 = (오늘 시가, 지금까지 고가·저가, 현재가를 종가 칸에, 누적 거래량) — 오늘 칸으로 붙이고 같은
  식을 쓴다(예: 장중 RSI = '지금 가격으로 마감한다면'의 값). quality `estimated`.
- `cross_*` 는 d−1 확정 칸 대 부분 봉 — 같은 날 여러 슬롯에서 참일 수 있어 쿨다운이 첫 슬롯만 보낸다.
- **장중 수급은 라이브**: 종목은 KIS 가집계 `KIS:inst_foreign_intraday`(10분 회차, `estimated`), 시장은
  `prv_gex.investor_flow` 1분 누적(쓰기 주인 `flows.market_minute` — ADR 0019). 오늘 칸 = 그 회차 누적
  순매수(원)를 넣은 원장 행, 어제까지는 확정 원장. 근거 문구에 **'장중 잠정'**. 가집계가 없는 종목·회차는
  그 조건이 **판단 불가**(`reason = no_live_flow`) — 규칙 전체가 참이어도 발송하지 않는다(지어내지
  않음). 마감 평가(`rules.close`)는 확정치로 다시 판정한다. 일치 감시는 잠정 → 확정 차이를
  `data_revised` 로 분류한다.

### 30.3 평가·쿨다운

- 조건 값이 `None`(워밍업·결측·정지)이면 그 조건은 **거짓 + 사유**(`insufficient`·`missing`·`halted`·
  `no_live_flow`·`split_suspect`) — 참으로 처리하지 않는다. `all` 은 잎을 모두 평가한다(근거에 전부).
- `cross_above`: 전 칸 `a ≤ b` 이고 이번 칸 `a > b`. `cross_below`: 전 칸 `a ≥ b` 이고 이번 칸 `a < b`.
  `turns_positive`: 전 칸 ≤ 0, 이번 칸 > 0(`turns_negative` 반대). 전 칸 = 칸 i−1(장중은 d−1 확정 칸).
- 판정은 3값(참·거짓·판단 불가 — 클리니 논리): `no_live_flow` 잎만 '판단 불가', 다른 `None` 사유는
  거짓. `all` = 거짓이 하나라도 있으면 거짓, 아니면 판단 불가가 있으면 판단 불가, 아니면 참. `any` =
  참이 하나라도 있으면 참, 아니면 판단 불가가 있으면 판단 불가, 아니면 거짓. 판단 불가 = 신호·발송
  없음(기록은 `skipped`, 사유 `no_live_flow`).
- 입력 지문 `input_fp` = 마지막 260칸 OHLCV·수급 값의 정규화 문자열 sha256 앞 16자.
- 쿨다운: 같은 (규칙, 종목)의 마지막 `sent`·`suppressed` 신호 시각부터 `cooldown_min`(기본 1,440 —
  하한 60)이 지나야 허락(미끄러지는 창, 경계 포함 = 정확히 그 시각이면 허락). `both` 모드는 장중·마감
  신호를 함께 본다. 막힌 시점도 `cooldown` 으로 기록.

### 30.4 신호 성과·백테스트 체결·일치 감시

| 지표 | 공식 | 예외·주 | 시험 |
|---|---|---|---|
| 신호 성과(h) | 진입가 P0 = 장중 신호의 슬롯 현재가 / 마감 신호의 그날 종가. `ret = close(D+h)/P0 − 1`(확정 일봉), `excess = ret − 지수 수익(같은 창 — 시장별 코스피·코스닥)`, `mfe = max(high[D+1..D+h])/P0 − 1`, `mae = min(low[…])/P0 − 1`. h ∈ 1·3·5·10·20 거래일 | 정지·상폐로 D+h 종가가 없으면 사유를 적고 통계에서 뺀다(뺀 수 표시), 분할 의심이 창 안이면 `split_suspect` 로 뺀다 | 손계산·sim 누적 |
| 성과 통계 | n·승률(ret > 0 비율)·평균·중앙·25/75%(선형 보간)·평균 초과·MFE/MAE 중앙. n < 20 이면 '표본 적음' | 문구 "과거 신호의 사후 수익 — 비용·체결 미반영" | 손계산 |
| 백테스트 체결 | 마감 신호 d → d+1 시가 체결, 보유 N 거래일 뒤 종가 청산, 손절·익절은 장중 low/high 기준(같은 날 둘 다 닿으면 손절 — 보수적), 장중 신호는 슬롯 가격 체결 | 정지일 체결 없음(다음 유효일) | 속성·손계산 |
| 비용 | 매수 = 가격 × (1 + 수수료 + 슬리피지), 매도 = 가격 × (1 − 수수료 − 슬리피지 − 거래세). 기본 수수료 0.015%(1.5bp) 양쪽, 매도 거래세 0.20% **[확인 필요 — 시행 연도 세율]**, 슬리피지 0 | 순수익률 = 매도 순액 / 매수 총액 − 1 | 손계산 |
| 거래 통계 | 거래 n·승률·평균·중앙·PF(이익 합 ÷ 손실 합 절댓값, 손실 0 이면 `None`)·MDD(복리 누적 곡선의 최고점 대비 최저 낙폭)·연환산(복리 총수익^(252/보유 거래일 합) − 1) | 거래 0 → 값 `None` | 손계산 |
| 일치 감시 | 같은 (규칙 판, 종목, 시점) 집합 비교. 차이 사유 = 입력 지문 같음 → `logic`(버그 — health 오류) / 다름 → `data_revised`(KIS 잠정 → KRX 확정·장중 잠정 수급 → 확정) | `logic` ≥ 1 이면 health 오류 | acceptance ④ |

### 30.5 저널·포트폴리오·상관·prefill·추천 성과 (로그인 — P8 묶음 JNL, ADR 0033 §2 — WRAP 이 옮김)

읽을 때 계산한다(표 없음 — 기록은 `prv_journal.*`, 쓰기는 `kbj.services.personal.journal` 하나). 돈은 Decimal(원)로 저장·계산,
응답은 원 정수(0.5 올림)·가격 소수 둘째. 시험: `tests/unit/engines/journal/**`.

| 지표 | 공식 | 입력·단위 | 예외·품질 |
|---|---|---|---|
| 평균 단가(이동평균) | 매수마다 보유 원가 += 가격 × 수량 + 수수료 + 세금, 평균 단가 = 보유 원가 ÷ 보유 수량. 매도는 평균 단가를 바꾸지 않는다 | 매매 기록(매매일, id 순) — 원·주 | 매수 비용을 원가에 넣는다 **[확인 필요 — SD 는 비용을 따로 뺐다]**. 보유보다 많이 팔면 `NegativeHolding`(422), 그렇게 만드는 삭제도 거절 |
| 실현 손익 | (매도가 − 평균 단가) × 수량 − 수수료 − 세금 | 원 | — |
| 평가 손익 | (최신 확정 종가 − 평균 단가) × 보유 수량 | 최근 5 거래일 안 마지막 확정 종가 — 기준일·품질 표시 | 종가 없으면 None |
| 월별 수익률 | (그 달 실현 + 평가 변화) ÷ (월초 보유 원가 + 그 달 매수 원가) × 100 | % | 분모 0 이면 None. **[확인 필요 — 현금 원장 없음]** |
| 상관 | 쌍마다 일간 수익률 피어슨 상관(기준 달력 마지막 60·120 거래일) | 관심종목 main 또는 보유 앞 50종목. 일간 수익률은 바로 앞 거래일 종가가 있을 때만(정지 뒤 첫날을 잇지 않는다) | 겹치는 날 < 40 이거나 분산 0 이면 None, 2종목 미만이면 404 |

## 31. 테마 강도·밸류체인 (로그인 — 페이지 9, ADR 0039)

- **입력**: 대테마(`pub_themes.theme` — 사용자 작성 분류), 대테마 ↔ 네이버 테마(`prv_themes.theme_link`), 편입
  (`prv_themes.member`), 종목 마스터(`prv_themes.stock`), 보드 종목 하루(`prv_board.stock_day` — 보드 마지막 날).
- **대테마 종목** = 그 대테마에 걸린 네이버 테마들의 편입 종목 합집합 ∩ 종목 마스터(한 종목 한 번).
- **등락(당일·5일·20일)** = 종목 `chg_pct`·`ret_5d`·`ret_21d`(보드 — 20일 = 21거래일 전 종가 대비, 수정주가 이상 구간
  제외)의 **동일가중 평균**(테마 안 종목 하나에 한 표) — 소수 둘째 자리 반올림. 단위 %. `weighted=false`.
  시총 가중은 쓰지 않는다: 네이버 테마 합집합이라 대형주가 여러 테마에 들어가고(삼성전자 13개), 시총 가중이면
  그 테마들이 대형주 하나를 복사한 값이 됐다(2026-10-20: 7개 테마 20일 −14.1~−14.7% ≈ 삼성전자 −14.89%,
  삼성·하이닉스 비중 80~96%). 보드 페이지 2 의 업종·테마 롤업은 시총 가중 그대로(시장 영향을 보는 화면).
- **거래대금 1위**(화면 '거래대금 1위' — 전엔 '주도주') = 아는 거래대금이 가장 큰 종목.
- **상승 비율** = 상승 종목 / 등락을 아는 종목(보합 = 정확히 0). 아는 종목이 없으면 None(0 으로 채우지 않는다).
- **신고가 수** = 보드 라벨(hist·w52·d120 — 52주 신저가 제외)이 있는 종목 수. **근접 수** = 보드 near_kind.
- **거래대금 배수** = 아는 거래대금 합 / 아는 20일 평균 거래대금 합(보드 규칙). **시총 합** = 아는 시총 합(원).
- **밸류체인** = valuechain 값이 같은 대테마들의 종목 합집합으로 같은 집계.
- **정렬**: 고른 기간(1·5·20) 값 내림차순, 값 없음은 뒤, 같으면 원천 순서.
- **품질**: 구성 행(편입 판·분류 판·보드 종목 하루) 중 가장 나쁜 것. 판이 `stale_days`(15일) 넘게 오래되면 stale, 공개
  분류 판과 편입 판의 built_at 이 다르면 stale + notes. invalid 보드 행은 계산에서 뺀다.
- **예외**: 분류 없음 → 404(theme.classes_sync), 편입 없음 → 404(theme.master_sync), 보드 종목 하루 없음 → 강도 404
  (board.daily) — 상세는 시세 칸 None 으로 200.
- **시험**: `tests/unit/theme/test_strength.py`(손계산·보드 롤업 대조), `tests/unit/api/test_routes_themes.py`.
